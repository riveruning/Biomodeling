# 科研 Agent 功能模块讨论草案

记录日期：2026-10-17。

**本文件仅整理此前讨论，不是已确认的产品需求、架构调整、开发计划、任务卡或验收标准。模块编号只用于讨论。未经用户明确确认，不据此修改代码或派发 DSH 工作。**

## 一、讨论中的产品目标

帮助研究者把论文中的机制解释变成有依据、可检验、可修改的数学模型，并逐步发展到候选机制比较和实验建议。

近期候选场景：研究者提交一篇小规模 ODE 论文，系统提取模型、指出缺失和冲突；研究者审核或补充后，系统继续模拟、比较结果并导出研究记录。

“近期候选”仍待确认。用户类型、首个完整任务与自主程度未定；不能由本文件推定为已选择的产品路线。

## 二、模块总览

| 编号 | 模块 | 用户获得的能力 | 当前基础与缺口概述 |
|---|---|---|---|
| M1 | 材料解析与证据管理 | 找到每条方程、参数和假设的依据 | 已有文本/PDF与引用追踪；图片公式读取和语义审核不足 |
| M2 | 模型构建与版本修改 | 将提取内容变成模型，并审查每次修改 | 已有草稿与 SBML 构建；字段约定、约束说明及交互式修改待完善 |
| M3 | 计算执行与科学验证 | 判断模型是否可计算、结果是否数值可靠 | 已有 ODE 执行和多项检查；通用守恒等能力仍有限 |
| M4 | 人工协作与任务续跑 | 回答系统的问题后接着做，不必重新开始 | 已能停止并记录问题；完整审核、补充和恢复流程未实现 |
| M5 | 参数估计与不确定性 | 知道哪些参数能估、预测有多确定 | 已有受限拟合及局部诊断；一般反应拟合与区间分析待扩展 |
| M6 | 候选机制构建与比较 | 比较多种机制对数据的解释与预测 | 已有有限合成候选闭环；真实案例和 Agent 工具接入不足 |
| M7 | 实验建议与区分能力分析 | 知道下一次测什么更可能区分机制 | 当前未建立经过验证的完整能力，属长期方向 |
| M8 | 研究工作台与结果交付 | 审查、修改、查看结果并分享研究过程 | 已有 CLI、报告和单次模拟研究包；交互界面与研究级复算待补齐 |
| M9 | 真实案例评测与对照 | 判断系统是否正确、是否节省人工工作 | 已有测试、数值基准及单篇开发试验；人审案例集与公平对照不足 |

这些是能力模块，不意味着拆成九个服务或九个 Agent。多个模块可以继续共享现有应用入口、存储与计算后端。

## 三、各模块的具体讨论项

### M1：材料解析与证据管理

职责：管理“来源说了什么、我们如何解释、哪些内容没有依据”。

- 保留原文、版本、页码或段落位置及解析结果。
- 提取方程、参数、初值、单位、实验条件和观测变量，明确区分不可读取与未报告。
- 为图片公式提供辅助转录或图像读取入口，保留原图与核对记录。
- 让研究者逐项审核证据是否真的支持对应解释，记录争议和冲突。
- 区分论文给定、研究者补充、拟合所得和系统假设。

候选交付物：可定位的模型要素—证据表及待核查清单。

讨论重点：图片公式先采用哪种协作方式？哪些依据必须人工确认？不同来源冲突时如何呈现？

### M2：模型构建与版本修改

职责：将结构化解释转为数学模型，并保留可审查的修改历史。

- 明确不同字段的 null、unknown、默认值和必填规则，避免模型靠反复试错理解接口。
- 检查符号、初值、单位、状态约束和后端支持范围，区分材料不足、格式错误与模型不兼容。
- 支持研究者修改方程项、参数、初值和观测映射，并显示修改前后的差异。
- 为每次修改记录理由、来源与父版本；标记是否已偏离原文复现。
- 当缺失信息和结构错误并存时，同时展示两类问题，不能把“等待输入”解释为只剩缺参。

候选交付物：版本化模型、差异记录和分类型问题清单。

讨论重点：先支持表单修改还是自然语言修改？如何让人核对自然语言修改的实际效果？

### M3：计算执行与科学验证

职责：按明确协议运行模型，并提供与结论范围相称的检查。

- 固定实验输入、采样时刻、初值、参数和求解设置。
- 处理不支持特性、数值失败和超时；给出可以操作的诊断。
- 维护数值稳定性、容差和参考轨迹对照；按模型声明补充守恒等检查。
- 分开呈现执行成功、数值可靠、来源支持和论文目标复现。
- 需要时增加后端或模型特性；每次扩展配套独立数值案例。

候选交付物：运行对象、检查结果、参考比较与环境记录。

讨论重点：下一批真实论文要求哪些计算能力？事件、随机模型或 PDE 是否真的阻碍首个场景？

### M4：人工协作与任务续跑

职责：把“系统停下来”变成“研究者可回答、可恢复的协作过程”。

- 明确列出缺失项、冲突、阻断原因以及各自影响。
- 接收补充来源、人工数值、语义审核或探索性假设，并记录操作者和决定。
- 区分严格复现、补假设重建和探索性模拟的执行条件。
- 从检查点继续执行，处理崩溃恢复，避免重复付费和重复计算。
- 修改输入后，识别哪些检查和下游结果需要重新执行。

候选交付物：问题与回答记录、审核决定、可恢复任务状态。

讨论重点：哪些决定必须由人作出？一次补充后如何知道之前的结论还是否有效？

### M5：参数估计与不确定性

职责：在明确数据和噪声假设下估参，并说明参数与预测的可信范围。

- 明确观测映射、噪声模型、参数边界、拟合目标和训练数据。
- 按真实案例需要支持一般反应模型拟合，记录多起点、失败和边界解。
- 加入灵敏度、参数相关性和可辨识性诊断，区分局部证据与全局结论。
- 选择适用的不确定性方法，例如 profile likelihood 或 bootstrap，传播到预测。
- 支持拟合研究完整保存和复算，而不只保存最优参数。

候选交付物：参数估计、诊断、预测范围与拟合研究包。

讨论重点：首期需要多复杂的统计能力？什么样的数据质量允许输出怎样的结论？

### M6：候选机制构建与比较

职责：把有限的机制解释变成可比较、可证伪的候选模型。

- 明确研究问题、允许考虑的机制、候选数量和计算预算。
- 从已有模型或机制模板构造候选，逐项标记新增假设。
- 包含简单基线，保持观测映射、噪声假设和比较协议可比。
- 仅用训练数据估参，冻结后比较留出条件或干预预测。
- 允许多个候选无法区分、所有候选均不足，不强制选出赢家。
- 将候选提交、拟合和比较接入 Agent 的受约束工具链。

候选交付物：候选模型集合、假设差异和比较报告。

讨论重点：先让人提出候选，还是允许 Agent 在小范围内生成？如何限制看过留出结果后的反复调模？

### M7：实验建议与区分能力分析

职责：在当前候选及其不确定性下，寻找更有区分力的测量或干预。

- 列出可改变的输入、可测量变量、采样时间及实验约束。
- 比较候选在不同实验条件下的预测差异，同时考虑参数不确定性和测量噪声。
- 对少量建议排序，解释依赖哪些假设、预计区分什么、可能因何失效。
- 先在已知生成机制的合成案例检验建议，再开展真实研究案例。
- 接收新实验数据后重新比较，保留原建议和预测。

候选交付物：少量附带理由、假设和预测范围的实验建议。

讨论重点：用户是否有真实实验条件与反馈数据？建议的可操作性如何审核？

### M8：研究工作台与结果交付

职责：为前述模块提供统一的审查与操作入口，并形成可交付记录。

- 展示原文、模型要素和待解决问题，支持逐项确认与纠正。
- 查看方程差异、参数、运行轨迹、验证结果和不确定性。
- 展示任务暂停原因，并支持补充后继续。
- 输出基于实际产物的报告，包含未解决问题、假设和适用范围。
- 扩展研究包，使模型、证据、拟合和比较研究可分享与复算。

候选交付物：最小交互入口及可复算研究包。

讨论重点：首个用户更需要 Notebook、轻量网页还是现有 CLI？先完成一个可用流程，再决定界面范围。

### M9：真实案例评测与对照

职责：持续判断能力、成本与科研价值，向其他模块反馈瓶颈。

- 建立少量独立人审案例，固定允许材料、参考答案和目标结果。
- 分开评分提取、依据、缺失信息处理、模型有效性和最终模拟；不能只报一个通过率。
- 记录人工修正次数与耗时、调用成本、失败类型和恢复情况。
- 在相同材料和可比预算下，对照通用助手、固定流程与 Agent。
- 将已用于开发的案例与后续盲测案例分开，保留失败和协议变化。

候选交付物：案例集、逐项评测和成本/人工工作量对照。

讨论重点：我们首先要证明“复现更正确”，还是“同样正确但更省人工”？

## 四、能力之间的关系

论文复现主线：M1 材料与证据 → M2 模型构建 → M3 计算与验证。
M4 人工协作贯穿三者，M8 提供操作与交付入口，M9 持续评测。

机制研究主线：在上述基础上，M5 参数与不确定性 → M6 候选比较 → M7 实验建议。
M5、M6 在实际研究中会往返迭代；这里的箭头表示能力依赖，不表示必须一次性顺序开发。

## 五、建议讨论的先后次序

| 阶段设想 | 重点模块 | 希望形成的完整能力 |
|---|---|---|
| 近期 | M2、M4、M9，配合 M1 审核与 M8 最小入口 | 一篇论文从提取、纠正、补充信息走到模拟验证，并能衡量人工工作量 |
| 中期 | M5、M6，继续强化 M1/M3/M4/M9 | 对真实数据完成有限候选机制的拟合、预测和比较 |
| 长期 | M7，依赖已验证的 M5/M6 | 提出有不确定性依据、可操作的区分实验建议 |

M3 已有计算基础，近期以可靠性和真实案例所需能力为主。图片公式读取按 M9 暴露的瓶颈推进。是否引入多 Agent、PDE 或其他技术，仍需单独讨论，不能由模块数量推导。

## 六、尚待用户选择的问题

1. 第一类用户是谁：学生、初次建模者，还是已有模型的研究者？
2. 首个完整任务优先选论文复现、模型修改，还是机制比较？
3. 人工审核的范围与探索性运行的授权边界是什么？
4. 最希望突出的价值是节省整理时间、减少建模错误，还是帮助设计下一步实验？

上述选择将影响模块优先级。在选择明确前，本文件只用于比较与讨论。
