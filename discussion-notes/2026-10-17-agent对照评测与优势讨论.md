# Agent 对照评测与优势讨论

记录日期：2026-10-17。仅用于讨论和调研，不是实际开发要求或评测执行授权。

## 核心判断

需要对照。项目的价值不能由功能数量、一次成功案例或底层模型名气证明。
拟检验的问题是：在生物动力学建模任务上，专用科学工具、证据与协作流程，是否让研究者以可接受成本得到更可靠、可继续使用的结果？

必须区分两种结论：

- 系统整体价值：研究者选择我们的系统，与选择一个通用编程 Agent 相比，结果和人工工作量如何？
- 方法贡献：使用相同底层模型和可比工具时，我们的工作流本身带来什么改进？

使用不同模型比较不同系统，可以回答前者；不能据此把差异全部归因于我们的 Agent 架构。我们的产品 Agent 可以调用 GPT 等模型，这与将 GPT 作为对照不矛盾。

## 建议的对照组

| 组别 | 条件 | 想回答的问题 |
|---|---|---|
| A：直接提示 | 同一底层模型，提供材料和任务，不带我们的专用工作流 | 专用系统相对直接使用模型增加多少价值？ |
| B：通用编程 Agent | 如 Codex，固定实际模型、工具版本和设置，使用它的正常工作方式 | 用户为什么选择我们的产品？ |
| C：固定科学流程 | 同一底层模型负责提取，后续采用固定检查/计算步骤 | 是否需要自主 Agent，还是固定流程已足够？ |
| D：我们的 Agent | 同一底层模型，使用受约束工具与工作流 | 当前产品的实际表现是什么？ |

方法分析可再加入 B 的受控变体：通用 Agent 获得相同科学计算工具和文档，但不使用我们的专用编排。它有助于区分工具的贡献和编排的贡献。
不必在第一轮同时跑遍所有模型、所有 Agent。先完成范围清楚的小型对照，再增加代表性的系统。

## 比什么

| 维度 | 可观察指标 | 防止误判的做法 |
|---|---|---|
| 最终任务完成 | 完整输入下的有效模型、轨迹误差、目标现象或留出预测 | 独立执行和科学检查；不看自报完成 |
| 提取与来源 | 方程/参数/初值正确性，引用位置与语义支持 | 项目逐项评分；独立人审有争议的语义 |
| 信息不足处理 | 无依据补值、缺失识别、针对性询问 | 同时测完整材料，避免总是拒绝也得高分 |
| 协作与恢复 | 完成所需的人工修改、人工耗时、补充后继续能力 | 统一可提供的补充信息，保存完整交互记录 |
| 复算与交付 | 独立环境重跑、关键输入与依赖是否完整 | 接受不同合理实现，不强制输出我们的内部格式 |
| 效率 | 实际墙钟时间、调用/工具/计算成本和人工成本 | 人工整理转录、配置及修复也计入；不只报 token |
| 机制研究 | 留出干预预测、不确定性质量、区分实验的效果 | 将拟合成绩和机制真实性分开；不能只看训练曲线 |

“保留来源”“支持续跑”“能导出研究包”是功能差异；只有测得它们降低错误或人工负担，才能成为有证据的优势。

## 最值得检验的优势假设

1. 在最终结果质量相当时，减少研究者修正模型和追查来源的时间。
2. 在保持有效提取和任务完成能力的同时，减少缺参时的无依据补全。
3. 在预算相当时，增加能独立运行和核验的研究产物，而非只得到合理的解释文字。
4. 在后续机制研究中，提高留出预测或区分实验的实际效果。

以上均是待验证假设。通用 Agent 也可能通过提示、工具或人工操作实现这些行为，不能预先宣称它们做不到。

## 如何尽量公平

- 冻结相同任务、材料、数据、允许的补充来源、人工帮助规则和外部检索条件。
- 系统整体比较允许各自采用正常实现方式；方法比较尽量固定模型和工具条件。不能混用两类结论。
- 提供清楚的环境与合理使用文档，允许各组在开发案例上调试，再冻结后进入留出评测。避免用刻意弱化的提示作为唯一基线。
- 分开记录“相同文本输入”和“相同原始 PDF/图像输入”。如果我们额外获得辅助转录，对照组也应获得同一份材料，或将转录列为单独实验因素。
- 接受数学上和科学上正确的 Python、SBML 等不同实现；按外部任务要求评分，不能因没有生成我们的内部对象就判对照失败。
- 把时间、费用、计算和人工介入作为明确预算。异构系统先选一个主要资源约束，报告其他实际用量；不能只匹配调用次数就称完全同预算。
- 允许系统合理提问，但使用事先准备的同一补充信息清单。研究者不能只对某组进行额外指导。
- 在完整材料与缺失/冲突材料上同时比较。区分正确完成、合理停下、无效拒绝、错误执行。
- 开发案例与留出案例分离，禁止访问参考答案、评分器和隐藏数据。运行隔离并避免共享上一次结果；记录模型版本、设置、工具版本、提示与时间。
- 多次运行，报告逐案例结果和波动。统计推断的独立任务单位通常是论文/研究问题，不能把同一篇里的多个字段当成独立论文样本扩大证据。
- 采用独立的结果检查；有条件时让审核者不知道输出来自哪组。确定性数值评分与专家语义审核结合，不能只依赖同一个 LLM 自评。

## 与已有评测工作的关系

以下来源用于借鉴评测设计，不是我们已运行的对照，也不能直接比较排行榜成绩：

- [CORE-Bench 原论文](https://arxiv.org/abs/2409.11363)：面向给定代码和数据的计算复现，并比较通用与任务专用 Agent。我们可以借鉴可执行产物和具体任务结果的检查；当前论文模型重建输入条件与其不同。
- [ScienceAgentBench 原论文](https://arxiv.org/abs/2410.05080)：强调具体科学工作流任务、专家验证及程序/执行/成本评估。适合借鉴分任务检查，而非仅宣称端到端科研能力。
- [PaperBench 原论文](https://arxiv.org/abs/2504.01848)及[官方实现](https://github.com/openai/frontier-evals/tree/main/project/paperbench)：将论文复现拆成细粒度评分项，并在独立执行后评估产物。它面向机器学习论文复现，不能替代我们的生物 ODE 案例集。

上述是对原始研究目标和设计的概述，不是它们当前最强成绩或最新排行榜的汇总。

## 适合本项目的阶段设想

第一阶段：用少量开发案例调通对照流程，包含材料完整、图片公式不可读、缺初值、语义冲突等情况。5–10 篇可以用于发现问题，但不预设足以证明普遍优势。

第二阶段：在独立人审、冻结协议和留出任务上，比较通用 Agent、固定流程与我们的 Agent。重点查看“正确结果所需的人工工作量”以及“完成能力与无依据补全之间的关系”。

第三阶段：根据结果做模块消融，例如保留计算工具但去掉专用编排，或移除证据检查；以较小、明确的对照检验各模块是否贡献实际改善。

实验结论允许为：仅交付与审计更好、部分任务更省人工、固定流程已足够，或者没有发现优势。根据结果调整定位，不能为维持优势叙述而更换指标。

## 当前能说与不能说的结论

已有基础：ODE 数值对照、测试、研究对象与引用追踪，以及一个真实论文片段的两组开发试验。
该试验中辅助转录后的 11 项核心内容匹配，但仍有格式和模型约束问题，没有完成论文模拟。

尚无证据证明我们超过 Codex、某个 GPT 模型或其他科研 Agent。对照评测的作用正是建立或否定这样的具体结论。

该讨论属于前一份模块草案的 M9；它应与 M2/M4 等模块迭代共同考虑，但本文件不授权实际开发或付费对照运行。
