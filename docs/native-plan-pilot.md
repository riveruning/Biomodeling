# 原生方案流程的真实模型先导

2026-10-29。接续[原生 submit_plan](native-modeling-decisions.md)。两个已见合成开发控制已由真实模型完成：单变量复现成功，缺参数时主动澄清。使用的是开发环境中的实验提示和传输变体；产品默认提示与传输尚未修改。

## 材料、授权与预算

三个新建合成案例位于 `benchmarks/inputs/native-plan-pilot-20261029/`：单变量产生/损失、双变量闭合转移、缺失速率参数。不是论文、实验数据或独立评价题。完整案例的解析误差门槛在执行前固定为 1e-5；缺值案例要求请求澄清且不执行。

用户明确授权向现有 USTC 路由 `https://api.llm.ustc.edu.cn/v1` 的 `glm-5.3-flash` 发送这三个案例、Agent 提示与反馈，最多 18 次请求；随后同意诊断。服务端模型 revision 未固定。本轮实际累计 **17 次请求尝试**，保守地包含授权前一次连接失败；已有返回、超时及仅预留的调用均计入上限。

每题原定最多 6 次调用、2 次修复、0 次自动传输重试、一次科学执行，上下文 60000 字符、输出上限 5000 token。诊断每次另建冻结任务，保留旧记录，跨任务共用 18 次请求上限。默认环境连接失败后停止；取得明确网络授权后才执行线上轮次。

单变量成功任务的实际动作是 `inspect_source → submit_plan → submit_plan → submit_plan → run → finish`。首次提案漏 `args.plan` 包装；第二次方案 ID 含连字符；两次均在模拟前被拒绝，模型根据原始错误自行修正。只有第三次提交通过。没有放宽验证器或替模型补写响应。

该成功任务服务返回用量为 **22318 token**（输入 19450、输出 2868）；缺参数任务为 **2378 token**。所有轮次的已知用量小计 **29580 token**，另有 **5 次请求缺失 usage**，因此整体 token 用量和费用仍为未知，不能把已知小计当作账单总量。完整逐条信息见[请求账本](../artifacts/native-plan-pilot-20261029/request-ledger.json)。

双变量案例本轮未做真实模型执行：最后仅余一次请求，不足以验证完整闭环。其离线可解性控制已通过，不能替代线上结果。两个线上开发控制各只运行一次，不构成成功率、基准成绩、因果消融或领域正确性结论。

## 诊断配置与依据

流式仅用于收取数据和诊断：正常 `stop` 与明确 `[DONE]` 均到达、JSON 完整解析后才返回 Agent 动作。截断、缺少结束标记、拒答、意外原生工具调用均拒绝执行。流读取间隔 timeout 为 45 秒，循环在收到事件时检查 180 秒期限，响应上限 2 MB；这不是独立于阻塞读取的整体硬期限。诊断只保存思考字符数和时序，不保存或展示思考正文。

官方说明 GLM-5.3-Flash 强制开启思考，`reasoning_effort` 支持 low/high/max，默认 max；所以本轮请求 low，未发送不支持的关闭思考参数。[思考模式](https://docs.z.ai/guides/capabilities/thinking-mode)、[API 参数](https://docs.z.ai/api-reference/llm/chat-completion)。USTC 是否完整透传该设置没有独立认证；观察到 low 变体能输出方案，不能据单次运行推断所有服务或模型的行为。

精简系统提示从首请求输入 1963 token 降至 971，但完整任务包含三次方案输出与逐项反馈，不能据提示缩短直接宣称端到端成本下降。后续应优先减少格式修复和重复上下文，再做固定任务的对照。
