# 可修订任务计划与依赖管理：R04

2026-10-25。已有 `workstate` 进度投影继续使用；本轮在其上增加**显式启用的有限 ODE 复现计划**、修订历史、执行前依赖检查和来源更新失效。任意任务分解和真实模型效果评价仍未完成。

## 启用与使用

Python 使用 `run_agent(..., task_planning=True)`；CLI 在原有 `agent` 参数上增加 `--task-planning`。现有任务及默认入口的行为不变。当前仅支持 reproduction 模式；hypothesis / frozen study 不开放此计划编辑能力。

Agent 初始任务包增加当前计划和修订规则。`inspect_progress` 与 `agent-progress` 会返回原有进度及 `task_plan`，其中包含当前计划引用、版本、调整原因、变化步骤、剩余修订次数、步骤依赖、状态、完成依据与剩余调用预算。

```bash
.venv/bin/python -m biomodel_agent agent --task-planning \
  --store artifacts/my-task --source source.txt --experiment experiment.json

.venv/bin/python -m biomodel_agent agent-progress AGENT_RUN_REF --store artifacts/my-task
```

第一个命令仍需按原有方式配置模型服务；第二个命令不调用 LLM。

## 计划及完成依据

固定主干为：`sources → draft → validate → execute → compare → report`。

| 步骤 | 程序读取的依据 |
|---|---|
| sources | 本任务实际来源范围 |
| draft | 最近一次提交产生的草稿引用 |
| validate | 最近一次提交为 ready、实际模型引用和时间单位检查 |
| execute | 当前模型的实际执行产物，必须与运行输入中的模型一致 |
| compare | 实际保存的参考比较结果；未请求参考时明确为 not_applicable |
| report | 完成条件检查后保存的最终任务状态，可由现有报告命令渲染 |

额外步骤只支持三类：读取指定授权来源 `inspect`、目标参数查证 `investigate`、核对冻结参数条件 `assess`。它们分别读取实际工具结果、查证产物和 assessment。查证完成仅表示查证过程产生了记录，不等于找到了可采用的值；条件核对步骤只有显式字段匹配才完成。

步骤状态可能为 ready、blocked、stale、failed、budget_exhausted、complete 或 not_applicable。LLM 不提交“已完成”或证据引用来签发状态；程序使用固定类型的完成判据。描述性的 goal 也不定义任意可自动证明的科学目标。

参考比较被明确纳入计划：冻结任务请求了参考却缺少固定误差尺度时，实际比较为 not_run，计划会保留未解决状态并阻止完成。参考不匹配也阻止完成。没有参考的任务仍可技术完成，但不获得参考比较通过的结论。科学支持继续为 unknown / not_verified。

## 有限修订

启用计划的 Agent 可调用：

```json
{
  "action": "revise_plan",
  "args": {
    "expected_plan_ref": "CURRENT_PLAN_REF",
    "reason": "新增参数查证，查证后重新提交草稿",
    "steps": []
  }
}
```

这里 `steps` 必须填入完整的 6–12 项步骤定义，不能是空列表。每项恰好包含 `id`、`kind`、`goal`、`depends_on`、`target` 和 `attempt_limit`；可从 `inspect_progress` 的当前步骤复制这六个定义字段，再进行有限修改。主干步骤的 target 为 null，额外步骤指定授权来源引用或参数目标。

- 保留六项主干及其必需依赖，允许增加查证/核对/阅读步骤并把它们接到后续步骤之前。
- 步骤标识唯一、依赖完整且无环；同一标识的类型与目标不能改写，也不能通过删除再创建来增加原有限额。
- 单任务最多四次模型发起的计划修订，每次也消耗正常的模型调用预算。无变化、旧版本引用、未知字段、伪造状态、扩大预算等请求拒绝。
- 每个版本保存前一版本引用、原因、变化步骤和调用位置；来源引用与历史版本属于不可变对象依赖，可随 bundle 导出。
- 修改某一步后，该步及其后继的旧完成依据失效。例如在已有草稿前新增查证，必须完成新查证并重新提交，不能直接沿用旧验证运行。
- 科学执行后不能修订计划来更换模型或再次试算；原有一次科学执行与冻结研究规则仍生效。

计划修订只安排现有操作，不改变实验、参考、参数适用条件、来源权限、求解器或研究协议。旧版本的原始定义可以通过当前 task_plan 对象的 `previous_ref` 逐级核查。

## 预算、重复操作及恢复

依赖未满足时在工具调用前阻断，并给出具体步骤。被阻断的动作仍消耗其已经发生的模型调用，不消耗科学执行次数。完全相同且仍有效的 ready 草稿不会重复构建；已有实际执行不会重复运行。

每步 attempt_limit 控制对应工具尝试次数，且不能超过冻结任务预算。新增步骤从其加入之后计数；后续修订、删除重加以及来源更新不能抹去该步骤已有消耗。预算针对当前任务接续链，不新增跨分支全局额度池。

收到研究者补充后，沿用原有署名回复和来源加入流程，程序追加一个 source_update 计划版本。它不消耗四次模型修订额度，但保留累计调用与步骤尝试；旧草稿/验证及后续完成依据失效。任意外部文件不能走这条接口偷偷扩大范围。

检查点、最终记录和上下文整理保留计划信息。修订及来源刷新写入既有调用日志：中断后只认领已返回、引用完整、与请求一致的版本；写出了计划对象却没有明确返回收据时继续保守阻断。实际执行之后再追加资料可能使任务需要新开，而不能借计划更新获得第二次科学执行。

计划信息也计入冻结的上下文字符预算；必要信息无法容纳时沿用原有停止与诊断规则，不截断关键状态来换取继续运行。
