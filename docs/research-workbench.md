# 本地研究工作台

2026-10-30。工作台把已有[统一任务入口](research-tasks.md)和[模型建议 / 来源模型草稿](task-proposals.md)接到同一个本地界面。模型契约、来源核对、计算预算、原任务续接与恢复仍由原有模块负责。第一版不增加运行依赖。

## 启动

```bash
.venv/bin/python -m biomodel_agent workbench --store runs/research-workbench --port 8765
```

打开终端显示的 `http://127.0.0.1:8765`。`--port 0` 可选择空闲回环端口。后端沿用本项目已有的 Linux/WSL 本地所有权协议，Windows 浏览器可访问该回环地址。

默认不调用模型服务。仍可导入资料/原生模型、创建和修订任务、导入已有建议、核对原文、显式采纳、查看已有结果、认领已保存的建议返回及导出结果包。页面打开、刷新和状态轮询只读取，不重新提交作业。

需要实际服务时，在终端配置凭证环境变量，并明确启用：

```bash
.venv/bin/python -m biomodel_agent workbench --store runs/research-workbench --port 8765 --allow-provider --base-url https://YOUR_PROVIDER/v1 --model YOUR_MODEL
```

默认凭证变量为 `BIOMODEL_API_KEY`，可用 `--api-key-env` 指定变量名；base URL / model 也可来自 `BIOMODEL_BASE_URL` / `BIOMODEL_MODEL`。凭证不进入浏览器表单或作业参数。服务地址不能含用户名、密码、查询或片段。

每次需要服务的操作先显示目标、材料范围、冻结输入/回复和所用服务；检查并确认后才提交。发送范围摘要与请求绑定，不能拿另一次任务或不同回复的确认替代。恢复已确认的原生结果只认领已有记录时，不需要服务。

## 从材料到结果

1. **导入资料或原生模型。** 浏览器选择 UTF-8 TXT / Markdown，或 FBA、随机、PDE、布尔、个体的原生 JSON。单个文件最多 1 MB。导入不会自动修改既有任务的授权材料范围。
2. **新建研究任务。** 填写目标，明确勾选来源、选择原生模型和类型；类型可以先留空。默认原生调用上限 6、建议上限 0。执行 JSON 放在可展开的高级配置中，遵守所选类型原有契约。
3. **检查模型建议。** 可导入本地/外部准备的建议 JSON，或在启用服务和建议额度后请求建议。查看备选、理由、原文、未知项、输入草稿和缺口。
4. **显式采纳。** 逐项确认知悉未知项，填写研究者标识与选择依据。生成新的任务修订；检查通过的完整来源布尔或 SSA 草稿会生成带来源的原生模型，仍不运行计算。采纳后的修订直接展示原建议和原文。
5. **执行与回答。** 前置检查通过后，核对发送范围再执行。等待研究者回答时，界面显示实际问题，回答沿用原 native task 和累计预算。原生模型不能通过回复偷偷改写。
6. **查看与导出。** 查看原生事件时间线和完整报告，下载 Markdown 或 ZIP 结果包。ZIP 中保留既有冻结闭包及只读检查说明；重新推理或科学重跑仍是明确的新操作。

ODE 的执行配置例子：

```json
{"experiment":{"times":[0.0,1.0],"time_unit":"second"}}
```

原生模型的执行配置例子：

```json
{"settings":{"steps":4,"seed":123,"timeout_s":15.0}}
```

第二个例子适用于对应布尔模型，不是六类通用设置。界面不自动补方程、规则、反应、边界或速率。高级 JSON 使用服务端严格解析，拒绝重复字段与非有限数值。

## 证据与科研边界

来源查看器显示页、字符偏移、原文及上下文，可翻页和分段阅读。切片在服务端按 Python Unicode 字符核对，emoji 等字符不会被浏览器 UTF-16 索引切错。材料、理由和报告按文本展示，不执行其中 HTML 或脚本。

“建议已保存”“草稿来源检查通过”“任务可以执行”“流程已完成”是不同层次。来源布尔路径仍仅支持整个授权范围最多 64000 字符、1–16 节点、无钳制的明确 UTF-8 声明；不从含糊激活/抑制文字推导规则。UI 上传不支持 PDF / FBC XML；CLI 已导入的来源可以按既有页文本查看，解析缺口仍须检查元数据。

新增[有限 SSA 来源路径](source-stochastic.md)：最多 8 物质、16 反应，核对整数初值、反应两侧、随机常数、逐反应单位及混合/动力学假设；候选中可展开数学草稿和单位绑定。不做浓度速率换算。FBA、PDE、个体继续使用已准备的原生载荷。数值完成不表示科学适用性已证实，研究者姓名或未知项确认也不构成独立领域审核。

## 作业、故障与恢复

界面动作使用单独的 `workbench_operation` 预留与不可变结束记录。同一提交标识不能换内容，重复提交只返回原作业。一个 store 的工作台串行处理操作，同 family 的排队/运行操作不重叠；已有原生所有权与科学调用账本继续生效。

长任务放在后台作业中，浏览器及时得到作业引用。任务状态来自原生账本，操作是否正在排队/执行可在“操作记录”查看；已有作业未结束时应等待，不另开恢复。结束记录必须在当前工作者完成索引提交后才向页面发布完成状态。

网络中断时浏览器保留提交标识，查询已有作业，不自动重发。服务器重启后，只有预留但无结束记录的动作显示结果未确认，不自动重放。操作失败也不能据此认定科学动作从未发生，应检查任务和原生账本。恢复逻辑继续拒绝未知效果重试；已确认的原生结果或建议返回可显式认领。

服务器会在退出前短暂等待作业；强制结束进程时未确认状态仍由账本保留。实现指纹改变后使用对应历史版本检查旧产物，或明确新建修订，不给旧结果重新认证。

## 当前界面范围

- 本机单用户工作区，不是公开部署或多人协作服务；仅监听 127.0.0.1。
- 侧栏显示最近 100 条任务记录；来源和原生模型选择列表也有数量上限。当前任务引用和修订入口保留，不能用列表顺序推断唯一研究分支。
- 上传最多 1 MB、HTTP JSON 最多 2.1 MB；工作台 ZIP 导出的未压缩总量最多 64 MiB，更大闭包使用已有 CLI 导出。
- 不提供取消科学动作、任意本地路径读取、任意工具执行、自动跨类型耦合、图形建模或发布功能。
- 本机请求核对 Host / Origin / 会话标识，不向其他站点开放 CORS。报告和下载通过当前本地会话读取。

## 开发演练与验收

```bash
.venv/bin/python benchmarks/development/demo_workbench.py --output artifacts/my-http-workbench-demo
```

输出目录须不存在。演练实际发起本机 HTTP 请求，六类流程和来源布尔暂停/续接实际计算；模型响应注入为脚本，不能当成线上模型表现。

需要在浏览器中手动体验合成服务时：

```bash
.venv/bin/python benchmarks/development/demo_workbench.py --serve --output artifacts/my-browser-demo --port 8766
```

这是明确标记的开发服务：只预置建议、追问和运行/完成响应，不会回退到任何真实模型服务。正常使用应运行前面的 `workbench` 命令。

本批结果、wheel、浏览器截图和异常记录见[工作台验收](validation/20261030/README.md#前序增量)。工程控制与合成演练不等于真实论文建模效果；线上使用、真实材料误阻断率和领域审核仍待验证。

后续增量 [SSA 来源构建验收](validation/20261030/README.md)另覆盖单位/假设展示、来源构建、缺速率和单位冲突，以及最终报告保留原文与选择。
