## 任务卡

### R01：让查到的参数能够有依据地进入模型

**原问题：** 用户或论文给出的值是否直接接受？数据库内容若始终不能用，知识库有什么价值？

**初步方案：** 先适配已接入的 SABIO-RK 原生记录，建立统一参数候选结构：符号及含义、反应、数值、单位、物种、温度、pH、测量/估计/假设来源类别、模型版本和原文位置。将“搜索—保存原始记录—纳入明确任务来源—条件检查—提出采用—提交前重检”接成完整流程。新来源加入应形成可追踪的任务版本，不默默改变旧冻结研究。

单位换算作为独立可检查产物，保存原值、目标单位、换算关系及结果，并核对模型时间尺度。先支持有限单位集合；浓度与物质量转换若缺体积等必要信息就保留缺口。不同条件下的同名参数分成独立候选，避免当前全局同目标标签检查把合理条件差异一律判作矛盾。用户设定保留为设定，拟合值保留为估计，不升级为测量事实。

**首次交付：** 原生字段适配器、条件化候选/采用记录、受支持的单位换算见证、接回 `assess_parameter` 和提交检查的案例。

**验收：** 匹配条件可采用；条件缺失或相反、原始来源更改、错误反应映射、同量纲不同尺度等情况各有明确结果。记录合法换算通过率、错误采用和过度阻断；数值跑通不能替代适用性依据。

**依赖：** 复用现有 knowledge、parameter_applicability、evidence 和模型单位检查；不从零重写检索。

### R02：参数找不到时，有数据就估计，没有依据就说明未知

**原问题：** 用户自己也不知道参数时，系统不应只能反复追问。

**初步方案：** 先检查可用数据、可观测变量、参数范围和拟合前提，再决定能否从普通任务提出一个独立估参任务。冻结训练/验证数据角色、损失函数、计算预算与参数边界，复用已有拟合核心。增加敏感性及多起点诊断；在预算允许且方法前提成立时，再给出参数或预测不确定性分析。

**首次交付：** 估参任务契约、参数出处类型、诊断报告与未解决问题。没有数据时仍可提出明确标注的探索方案，但不能据此完成严格论文复现。

**验收：** 用可解析的简单合成数据检查已知参数恢复；用只能识别参数组合的案例检查系统能否报告不可区分，而不是输出虚假的唯一真值；保留拟合失败及验证误差。

**依赖：** R01 的参数身份/来源表达、R04 的任务分支，以及数据范围明确。此项不是给现有拟合函数加一个自动调用按钮。

### R03：把零散资料整理成能复用的模型案例

**原问题：** “知识库里到底有什么”“是否能提供文章复现资料”“能否边用边扩充”。

**初步方案：** 先用已有且允许使用的开发材料整理少量案例，统一包含模型文件、方程与符号映射、参数/初值、适用条件、来源、运行配置、参考结果、已知缺口和验证层级。提供案例目录与按需加载；加载动作显式把选中资料纳入任务。任务中发现的新资料可提交候选，保存原始响应、版本、重复/冲突检查和审核状态。

**首次交付：** 案例包格式、现有材料的案例目录、案例加载和 `propose_knowledge` 类候选入口。原始资料保存与衍生结论采用分别记录。

**验收：** 一份完整案例能从干净任务中加载并重跑；缺初值的案例仍显示缺口；错误版本不会悄悄替代原包；评测答案和独立留出材料不进入可检索案例库。

**依赖：** R01；复用现有存储，不因“知识库”这一名称就引入大型向量服务。

### R04：从固定进度表升级为有依赖的任务计划

**原问题：** 每轮选下一步是否容易漏步骤、重复操作？如何知道当前还差什么？

**初步方案：** 新增版本化计划：步骤目标、依赖、需要的资料、预期产物、完成判据、预算和阻塞原因。LLM 可提出计划或修订；程序验证依赖、允许的工具及预算，完成状态仍由真实产物推导。改变来源、模型或参考结果时，按依赖使相关检查失效，保存修订原因与前后版本。

**首次交付：** 一个受支持 ODE 复现模板及有限编辑接口，覆盖查证、建模、验证、参考比较与报告，再决定是否扩展任意任务分解。

**验收：** 补充初值后能接续正确步骤；修改参数后旧验证不会继续显示有效；不会漏掉参考比较、反复运行已经完成的同一步，恢复后保留累计预算。计划不得改变冻结研究的科学协议。

**依赖：** 现有 workstate 和调用日志；与 R01 的查证缺口对接。

### R05：把错误建议变成可验证的修复行为

**原问题：** 系统报错后能否知道修改哪里，而不是只返回失败或重复尝试？

**初步方案：** 在已有诊断和结构化反馈上补策略表：格式/引用错误允许定向重提；资料缺失转检索；来源冲突展示差异并追问；数值问题检查结构、单位与求解诊断；服务问题仅在能够确认重试不会重复产生效果时有限重试。未知执行结果仍交由既有恢复机制处理。

**首次交付：** 有次数/总时间预算的处理策略、重复错误识别、无进展停止条件和每次修复差异记录。

**验收：** 预先固定一组错引、单位缺口、冲突、数值失败、服务中断案例。报告正确修复率、新错误比例、误阻断、人工介入和调用成本；不能靠放宽科学检查提高“完成率”。

**依赖：** R04；复用 diagnostics、validation_feedback 和受控恢复，不重复实现调用日志。

### R06：让经验能够积累，同时在更正后可靠失效

**原问题：** Memory 有什么实际帮助？能否由 Agent 提炼经验？长任务如何不丢掉关键信息？

**初步方案：** 在现有操作者候选流程上，增加 Agent 提议入口，候选必须引用真实任务事件和适用范围。审核、启用沿用已有机制。原始资料、当前任务状态、历史经验分别保存；上下文保留当前计划、模型、未解决冲突、有效证据索引和预算，细节按需回读。

**首次交付：** 自动提议但不自行批准的候选流程，以及来源/模型/经验更正后的依赖失效检查。先测量查询规模与成本，再决定是否换记忆后端。

**验收：** 待审候选不进入有效经验召回；撤回后不能通过旧摘要复活；跨项目/跨条件不串用。设计多会话“首次失败—记录经验—相似任务—原经验更正”的对照，比较重复错误、证据遗漏、完成质量、token 和耗时。

**依赖：** R04/R05 提供清晰任务和错误记录；R11 提供真实效果评价。记忆中的数值不能替代本次模型依据。

### R07：科研 Skill 对应实际工具、产物和停止条件

**原问题：** Skill、Tool 和专业软件分别做什么？新增流程是否真的增加科研能力？

**初步方案：** 把每项 Skill 规范为适用场景、所需输入、可调用工具、步骤、预期产物、验收和停止条件。优先补“参数查证与来源采用”“参考结果比较”“失败诊断”；估参和 FBA 指引等对应工具接通后再开放。

**首次交付：** 版本化技能清单、能力依赖检查及每项技能的一份实际运行示例。

**验收：** 工具未接通时不宣称支持；流程遇到条件缺失会保留问题；加载指引不会无控制地挤占上下文预算。技能效果通过有/无技能对照衡量，不能用文档长度或技能数量验收。

**依赖：** R01/R05/R10；新模型技能依赖 R09。

### R08：减少论文转纯文本时丢失的公式与表格

**原问题：** Goodwin 的 raw 输入只有图片占位符，为什么不能从论文建模？

**初步方案：** 先用已有开发论文明确缺失来自扫描、图片公式、表格错位还是阅读顺序；再接一项成熟本地 OCR/公式识别能力的薄适配。保留原页、裁剪区域、文字/公式候选、坐标和工具版本。低置信或矛盾内容进入核对，不默认为正确转录。

**首次交付：** 有限页面类型的解析适配及原文定位；将转录作为派生产物接回当前来源流程。

**验收：** 相同材料的原始输入与审核转录分开测，检查符号、上下标、负号、数值、单位和表格配对；再看端到端模型是否正确。解析失败不能自动解释成论文没有提供信息。

**依赖：** 现有 PDF 适配和绑定检查；具体组件需在实施时按样例、许可、运行环境与效果选定。

### R09：先完成一种 ODE 之外的建模类型

**原问题：** 能否支持任意生物系统建模，而不局限于 ODE？

**初步方案：** 沿用已做可行性研究的 FBA 路线，先复算公开教材原问题。建立原生模型契约和受支持 FBC 导入，明确计量矩阵、通量边界和目标；封装现有线性规划求解器，增加执行期限、有限性/平衡/边界检查、不可行/无界状态、存储报告、CLI 和 Agent 类型路由。

**首次交付：** 从模型导入到报告的完整产品流程，并明确不支持哪些结构。保留现有 ODE 表达和执行路径。

**验收：** 分析解小网络、不可行/无界/错误输入先通过；再与已保存的教材原问题参考目标比较。相同目标可能对应多个通量解，不以逐项通量相同作为通用要求。已有两种 HiGHS 方法不能称作两个独立求解引擎。

**依赖：** 现有 FBA 探针；R04 的能力路由。其余随机、PDE、布尔及个体模型继续作为后续候选，先完成单类型验收。

### R10：把数值互验与论文结果复现明确区分

**原问题：** SciPy 曲线是否就是作者原图？我们到底有没有复现论文结果？

**初步方案：** 在来源充分且允许使用的开发案例上，优先寻找作者原始数据；若只有已保存图像，制作带坐标标定、提取误差和审核记录的数字化参考。比较指标与相位/时间对齐规则事前确定，分别报告工具间一致性、与文献参考的一致性及科学解释。

**首次交付：** Goodwin 既有案例的定量参考比较报告，注明探索初值、稳定段选取与缺失信息。原始数据无法获得时如实限定结论。

**验收：** 他人可从原图/数据、标定、模型和配置重建比较；不能在看见结果后随意调参、平移相位或改阈值来追求重合。初值未知时优先比较有依据的稳定周期和幅值，不声称已重现原始瞬态。

**依赖：** 现有 Goodwin 原图、模型和运行记录；R03 的案例包。需要独立的模型实现检查与来源检查，两个求解器共享错误方程时仍可能一致。

### R11：证明实际有效，而不是用测试数量代表科研能力

**原问题：** 三批测试材料成熟到哪一步？比较对象和指标是什么？项目是否优于通用 Agent？

**初步方案：** 分四个可独立追踪的子任务：

1. R11a 材料与审核：核对材料池、可运行开发题、待审题和正式可评分题的状态；形成任务输入、来源支持、数值参考、允许的澄清和逐项评分表。现有18例检索正式审核未完成。真实项目资料池不能直接算成同等数量的 Benchmark 题。
2. R11b 真实系统先导：在服务与材料范围明确后，完成实际产品和原生 Codex 的调用/执行/导入流程。固定任务、预算、人工回复及数值评分，保留失败和缺跑分母。
3. R11c 同模型归因与消融：分开实际系统比较与同底层模型的框架比较；后者再检验证据约束、澄清恢复，以及 RAG/Memory/Skill 是否改善结果。
4. R11d 正式评价：先导后冻结版本与指标；按论文或机制家庭划分开发/评测，不把重复运行算作独立任务，独立领域审核与程序数值评分分别记录。

**首次交付：** 既有材料的状态清单、评分规范和小规模真实先导计划；正式数量由先导误差和研究目标确定，不凭空承诺样本数。

**验收：** 报告正确完成、无依据执行、过度阻断、有效追问、澄清后恢复、人工介入与资源；已通过、已失败、未审核分开。每个成绩能追溯到真实调用及产物，不把脚本响应计入真实模型成绩。

**依赖：** R11a 准备可立即开展；真实运行取决于已明确的服务/材料范围，独立审核取决于实际审核人。遵守既有留出隔离和材料访问限制，本方案不新增访问或外发许可。

### R12：让文档与任务交接准确反映实际完成情况

**原问题：** 多轮聊天的早期状态和最新交付混在一起；五小时续作并未按计划完成后续阶段。

**初步方案：** 建立一个当前状态入口，每项保留问题、负责人/执行者、依赖、当前状态、最近产物、验收记录和下一动作；历史文档注明适用版本。执行交接记录开始、最近进度、结束、截止时间和阻塞原因；自动触发与真实执行记录分别核查。

**首次交付：** 对齐 backlog 总表与旧复选框、T15 的“待调研”和已存在的探针、旧“下一步”及当前剩余任务。后续有授权的持续执行采用短交付周期并记录每段真实结果。

**验收：** 从统一入口能回答“完成了什么、依据在哪里、剩什么”；用中断/延迟触发演练检查截止后不会启动新开发；创建自动化不能标成开发已经开始。本次旧自动化保持暂停，本方案不承诺它会持续运行。

**依赖：** 各任务的真实产物；R04 提供产品内任务状态。本项还包括开发交接，两者不混成一个运行状态。
