# Agent 研究项目与论文开发队列验收

本轮按“人提出应用场景，Agent 决定研究细节”的目标增加研究外层。主流程、边界、CLI 和队列配置见[使用说明](../../agent-research-projects.md)。本记录对应 Windows 适配之前的冻结研究增量；整理基线位于 `riveruning/Biomodeling` 的 PR #2。研究功能后续随原生 Windows 纯运行版交付到 `FrostingMaple/Biomodeling`，跨平台结果另见 [Windows 交付记录](../20261031/windows-runtime.md)。

## 本轮变化

- 研究方案记录对象、粒度、证据需求、假设与冻结判据；Agent 可以修订并创建关联的新实验。
- 讨论保留具体问题与具名回答。批准建模粒度不能替代数值、来源或参考验证。
- 完整原生输入直接计算；显式 ODE 方案也调用原执行器，避免只做运行/结束的内层请求。
- Agent 能检索与读取同项目文献，从授权 UTF-8 数据中选择字面 CSV/JSON 参考，冻结提取位置、映射与数值；这些数据不自动成为独立证据。
- 论文开发队列保存各案例的流程诊断与未激活经验候选；分别统计声明的论文标识、材料、案例与家族。
- 历史核对合并扫描，继续从实际对象检查预算与归属，不依赖可删除的 SQLite 索引重建调用额度。

## 发现并修复的问题

浏览器发现新建项目的循环变量覆盖了客户端操作标识，造成查询无法接续；已修复并补回归。初始加载时立即新建存在资料目录尚未返回的竞争，已修复。手机布局的长引用已换行。

重复项目演练暴露历史逐操作重复扫描。改为一次归集关联返回后，当前单项目演练第二段约 16.4 秒；此前两个项目共享存储时曾观察到 120.6 秒。数据规模和同时运行负载不同，不能据此宣称严格的倍数提升；读取工作量上界另有回归检查。

公开接口试用中，`EXT_ID:PMC4383902 AND SRC:PMC` 零命中；使用 `PMCID:PMC4383902` 后命中并取得全文。该文章的规范记录来自 MED。这是实际查询诊断，不把零命中直接认作没有证据。

本轮保留了两次原有 0.2 秒截止测试在完整运行中的失败：截止时尚未记录模型请求，测试期望 1、实际 0；隔离复测及所在模块 50 项通过。为明确验证“中断已经进入的慢请求”，仅将该用例窗口改为 1 秒，仍模拟 5 秒请求，保持 3 秒内终止、请求数为 1 和监督器启用的断言。产品截止规则与计数逻辑未改。完整结果不隐藏此前失败。

## 科研与权限边界

所有研究控制中的模型响应均为脚本，未请求新的外部模型服务；未使用独立评价集。公开 API 烟测仅验证接口，实际论文复现数仍为 0。真实 LLM 的证据判断、研究规划、修复成功率和 token 收益均未由本轮证明。

XML/PDF 复杂公式、图表与任意补充数据仍有解析缺口；跨案例学习只接收有界诊断摘要，候选不会自动进入后续科学输入。完整计算不代表机制适用，领域独立审核保持未知。

原 93 个测试文件及输入中，92 个保持不变，另 1 个仅作上述截止测试稳健性修正；所有变化可与基线摘要核对。新增控制不替代原有检查。历史源码、原始失败、研究记录和旧版本指纹保留，未把旧记录改签为新实现。

主要本地记录在 `artifacts/research-projects-20261030/`：`frozen-delivery.json`、`history-regression.xml`、`key-regression.xml`、各次完整回归、`source-demo-release/`、`installed-demo-delivery/`、`browser-delivery/` 与 `public-literature-smoke-pmcid/`。这些原始对象和运行资料不随普通源码分发。
