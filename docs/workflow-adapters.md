# T08b：三种工作流执行适配器

本轮完成可执行的固定流程、通用工具 Agent、领域 Agent 适配，以及共用的请求记录、工具预算、进程监督、原任务恢复和 T08a 结果归一。领域组直接调用产品 `agent.run_agent` / `agent.resume_agent`；没有用另一套脚本替代产品 Agent。

适配器位于 `benchmarks/development/workflow_adapters.py`，统一驱动位于 `benchmarks/development/run_agent_comparison.py`。T08b 交付时产品源码、旧测试、T08a 协议与历史成绩均保持不变；后续 F1 只修改共同绑定语法，见下文。仍采用单个逻辑 Agent 和确定性科学工具，没有引入产品多 Agent。

## 三组相同与不同的部分

| 工作流 | 控制方式 | 共享后端 |
|---|---|---|
| fixed_workflow | 自动读取当前授权材料；一次模型提取或追问；就绪后确定性构建、运行和结束；不转为任意工具循环 | 相同的来源读取边界、`agent_tools.submit_draft`、`application.run_reproduction` 与科学验证 |
| generic_tool_agent | 通用工具契约和循环；模型选择读取、提交、运行、结束或追问，不附加领域提示指引 | 同上，保留绑定、时间单位、非负性和单次科学执行约束 |
| domain_agent | 使用产品的领域提示、内部状态机、检查点和原生澄清恢复 | 同上，实际运行现有产品 Agent |

领域提示和编排差异是比较因素。此处通用组并非不受任何科学约束的聊天助手，固定组也包含一次 LLM 提取；三组共用严格工具后端，不能据此评价“领域工具整体相对无工具系统”的增益。产品的 Memory、检索、Skill、study 工具在本轮共同工具集合外；领域提示仍是原产品提示，传输前附加本轮能力边界，调用集合外工具会被拒绝。模块消融尚未进行。

运行阶段预留 simulate 和 validate 两个预算单位，来源读取与构建各一个；科学验证含在同一个产品运行调用中。这是共同操作预算，不等于底层积分器调用数：正常运行另有收敛加严积分，已有报告如实另列。固定流程读取由控制器发起，通用/领域组读取由模型发起；全部计入工具预算。各组可用同一上限，实际调用量可以不同。

## 共同请求、预算和记录

适配器只接收 T08a 的当前阶段投影，不接收 private_rubric 或未来澄清。注入的 transport 提供 `model_config`、`evidence_kind` 和 `request(payload, timeout_s)`。每次实际请求明确传入共同的 model、temperature、top_p、seed（非空时）、max_tokens。三组使用相同的严格动作解析器。

本轮不创建线上客户端，不查找凭证、读取 DSH 配置或选择服务地址。CLI 只接受显式 scripted_control；库接口可注入之后经授权的传输实现，实际同底层模型的在线对照尚未开展。返回的 model 标识不一致会在执行动作前拒绝；未返回标识只保留未核验状态，自报标识相同不构成提供方模型身份认证。

预留记录在请求或工具副作用之前保存，失败不退款。产品 Agent 的工具调用通过持久调用日志预留点计入同一外层预算，没有修改或临时替换产品函数。调用量、工具量、活动耗时在澄清前后累计，最多尝试一次科学执行；新输出路径不能在同一存储中重复执行同一 trial_id，未知/部分执行不自动重试。

实际发送的完整请求、合法响应文本、原生 usage、声明/返回模型和操作预留作为不可变产物保存。wrapper 附加的评价提示也包含在实际请求审计中，不能只用产品内部未附加提示的历史代替实际请求。异常仅记录类型及受控错误说明，不保存凭证、HTTP 头或原始传输异常。

上下文按实际发送的消息 JSON 字符限制，不是完整 HTTP 字节数或 token 计量。单次 max_tokens 作为请求约束；若服务报告超限，停止后续动作。未报告输出 token 时保持未知，不能声称实际 token 上限已经独立验证。缺失 usage 仍为 null，没有基于字符估算费用。所有缺跑、错误和暂停记录进入 T08a 固定分母。

## 总期限与失败恢复

每阶段在 POSIX fork 工作进程中执行，外层监督剩余累计活动期限；超时终止进程组，并回收已知 multiprocessing 子进程。该实现针对当前 Linux 环境，不是通用跨平台执行器，也不承诺任何任意外部进程都能完整回收。科学后端保留其自身的子进程超时。

中断后保留来源、预留、请求、已有结果和失败收据。executed 字段表示已预留并尝试进入科学执行，不保证得到完整轨迹；具体结果及完成情况另见 run_ref。只有确有结果时才记录成功或相应科学状态，不根据模型宣称生成模拟产物。进程创建和清理计入阶段实际耗时，工作期限结束后的有限清理时间也会如实反映在遥测中。

恢复要求内容寻址的父会话记录，同一计划、工作流、案例、重复号、提供方类/声明配置、预算、工具指纹和原材料前缀均须一致。领域组使用原生 `resume_agent`，其他两组保存并继续原有对话、来源、任务和预算；新来源保留 research assertion 归属。父任务失败或已结束时，澄清阶段记为 not_run，不新开一个付费任务冒充恢复。恢复路径失败时也不退回 fresh 重建。

本轮澄清是冻结协议的预录文本，并非真人现场回复，人工介入和等待时间均为 0；实际追加来源与原生父任务关系单独保存。对任何 awaiting_input 都按计划提供该预录回复，不自动判定问题语义是否适当；针对性追问和成功恢复的评价仍需归属审核。

Python transport 与适配器属于受信任的执行代码。当前输入投影防止正常调用把参考标签传给模型，不是阻止恶意 Python 回调读取任意本地文件的操作系统沙箱。

## T08b 原始离线演练及限制

复用 T08a 的完整 decay、缺初值 translation、公式歧义 logistic，三组各两次重复，共 30 条阶段记录。模型决策来自明确标注的字面脚本，所有构建、SBML、求解和产品验证实际执行；**脚本决策不是模型能力证据**。

- 58 次脚本 transport 调用，线上模型调用 0；30 条记录全部保存。
- 12 个阶段完成实际严格模拟，另有 12 次收敛加严积分；无缓存复用。decay、translation 各 6 次，跨工作流和重复的轨迹最大差异为 0。
- 12 个初始缺口阶段按脚本追问。6 个 logistic 澄清阶段继续等待：原文 “The author confirms the intended equation is …” 不在现有绑定声明语法内，三组均返回 binding unknown。没有重写材料或放宽产品规则隐藏这一共同限制。
- 所有 T08a assessment 保持 unreviewed，数值/来源判断和行为标注不自动填 pass。因此技术完成不能直接成为已审核的正确完成或模型成绩。

实际轨迹对解析解的误差完整记录在[数值诊断](../artifacts/audit-t08b-workflow-adapters-20261019/scientific-results.json)。最初临时设定的绝对 2e-6 诊断断言在 translation 上失败，原始输出保留于 scientific-results-first.log；没有换一个更宽阈值宣布该精度通过，也没有更改求解设置或轨迹。已有有限性/收敛判据与全局绝对误差是不同证据，不对任意 ODE 承诺全局误差小于求解器局部容差。原始与加严积分误差均列出，科学状态仍为 not_verified、semantic_support 为 unknown。

首轮新增 20 项通过。扩大科学一致性检查后，复现并修复了基线组漏传非负约束、领域组误读完成事件两处问题；中间实现错误与修复日志保留。最终定向 97 项通过（新增适配检查 50 项，加原 T08a 47 项），完整 **1172 项通过**（278.90 秒），源码差异见[工程验收](../artifacts/audit-t08b-workflow-adapters-20261019/acceptance.json)。

## T08b-F1：完整声明语法与原样重跑

共同绑定工具增加 `The intended equation is ...` 和 `The author confirms the intended equation is ...` 两种固定 ODE 声明，保留完整确认前缀的位置。截短引用、否定、不确定、条件限定、错误目标与不同公式仍不能匹配；语义支持保持 unknown，科学状态保持 not_verified。[支持边界](evidence-binding.md)与实际 SBML 重检规则均保留。

新增 63 项开发检查，修改前修正后的基线为 16 失败、47 通过。首份基线另有两项过严的状态预期：旧语法可将 “It is ...” 保守拒绝为 mismatch；在产品修改前改为接受 unknown/mismatch 两种拒绝。两份原始记录保留。首轮定向 223 通过、1 项原有的 0.6 秒领域组超时控制失败：期限在科学预留前耗尽；完整 meter、结果与存储已另存。随后原三组超时检查 3 项通过，完整原样回归 **1235 项通过**（约 302 秒），没有修改旧测试或超时门槛。

新建冻结清单仅改变 toolchain_sha256，材料、实验、字面脚本、模型设置和预算与 T08b 原件一致。旧清单在提供方调用和创建输出前拒绝执行，恢复版本检查未放宽。原 T08a/T08b 产物和失败记录全部保留。

原样重跑的 30 阶段使用 66 次脚本 transport 响应，线上模型调用 0；18 个阶段完成严格模拟，另有 18 次收敛加严积分。原六个 logistic 澄清阶段全部继续执行，12 个初始缺口阶段仍追问。产品领域 Agent 确实恢复原生父任务，其他组继续其原会话。decay、translation、logistic 各 6 次实际轨迹，跨三组/重复最大差异均为 0；原先完成的 12 次时间网格、数值、后端、单位与运行状态一致，运行耗时另作遥测。

解析解误差按原设置报告，没有新设全局误差通过门槛；旧的临时 2e-6 失败保留。所有评价仍 unreviewed，没有独立领域决定或正确完成率提升结论。详见 [F1 工程验收](../artifacts/audit-t08b-f1-equation-prose-20261019/acceptance.json)及[实际数值诊断](../artifacts/audit-t08b-f1-equation-prose-20261019/scientific-results.json)。

## 重跑

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python \
  benchmarks/development/run_agent_comparison.py \
  --manifest artifacts/audit-t08b-f1-equation-prose-20261019/control-inputs/manifest.json \
  --scripts artifacts/audit-t08b-f1-equation-prose-20261019/control-inputs/scripts.json \
  --output /tmp/agent-comparison-new-run
```

输出目录须不存在。上例使用 F1 新指纹清单；旧 T08b 清单仍是历史记录，当前实现会拒绝。未来再修改产品后也须冻结新的清单并保留旧版本。脚本输入必须恰好覆盖计划条目，字面动作里的 `$main`、`$reply`、`$main_length` 只从实际请求可见的来源元数据解析；没有内置从参考答案生成响应的逻辑。准备脚本是单独标注的开发控制作者代码，不是产品 Agent。

驱动逐阶段保存 records 和 receipts。意外前置条件错误会保留已有产物并停止，原计划中未执行项仍可用 T08a 工具按固定分母汇总，不自动删掉失败或重跑。CLI 成功退出只表示驱动结束，应检查操作状态、技术状态、预算未知和未审核字段。

后续 [T08c 共同 HTTP 传输](comparison-transport.md)已完成离线工程验收：74 项专项、1309 项完整回归通过；新增传输身份摘要及逐次收据，同类更换服务地址/配置不能恢复旧任务。旧注入接口兼容，产品源码、评分器与原脚本不改。原样 30 阶段 HTTP 模拟有 66 次请求、18 次实际严格模拟及 18 次加严积分，原任务关系与数值均核对；依然是 scripted_control，不计真实模型表现。

T08 整体仍缺实际模型对照、独立审核任务及模块消融。用户将主要对手定为 Codex，候选先记 gpt-6.1-sol、gpt-6-astra（暂按“Atra”理解），具体服务配置稍后讨论。下一项 T08d 先准备真实 Codex 执行与记录协议、共同材料/预算及工具环境差异，另保留同底层模型三工作流对照以区分框架贡献。服务配置和具体材料范围明确后再在适用授权内执行；T08c 准备包本身不授予外发授权。T07 的独立审核/真实论文证据仍待补；本轮没有新增论文、读取独立评测集、访问 c13/c18 或重试被拒绝的 USTC 外发。
