# 检索开发基线与可选片段排序

2026-10-19。本轮只改善授权材料内的检索，不调用外部模型，不增加依赖或 embedding。单 Agent、来源白名单、调用与科学验证预算保持原约束。

## 问题与兼容

`lexical_v1` 按整页命中的不同查询词计分，每页只返回第一次命中附近至多 600 字符。同页后面的参数值、公式或冲突陈述可能没有进入结果；页的 matched_terms 也可能出现在返回文字之外。这是旧版公开行为，本轮保留。

新增 `passage_v2`，通过显式选择启用。Python API、CLI 和新 Agent 任务仍默认 `lexical_v1`，不因小型开发集的正向结果就更换所有任务协议。Agent 把所选方法写入不可变任务，恢复继续沿用；旧任务缺少该字段时采用 v1。模型只能提交 query，不能选择方法、扩大来源或预算。未知的方法版本在恢复写入研究者回复或调用模型之前拒绝。

```python
search_sources(store, source_refs, query, method='passage_v2')
run_agent(store, provider, source_refs, experiment, retrieval_method='passage_v2')
```

```bash
.venv/bin/python -m biomodel_agent source-search --store STORE \
  --source-ref SOURCE_REF --query 'initial X' --method passage_v2

.venv/bin/python -m biomodel_agent agent --store STORE \
  --source paper.txt --experiment experiment.json --retrieval-method passage_v2
```

第二条需要正常模型服务设置且会调用模型。本轮没有执行该在线命令。

## 片段方法

- 按原文空行分段，将短段打包为至多 480 字符；长段采用 480 字符窗口和 256 字符重叠。重叠至少覆盖最大合法查询词长度，避免单个长符号在所有窗口边界都被切断。
- 在原文上以 Unicode 完整词边界进行大小写不敏感匹配，保留下划线与数字。例如 `k` 不匹配 `kcat`，`Na_K` 不等于 `NaK`。不承诺中文分词、同义词、符号语义或任意大小写折叠等价。
- 先按片段命中的不同词数，再按截断到每词最多 3 次的命中频率/片段词数排序；相同得分依次按输入来源顺序、页码与字符位置排序。不使用答案、目标数值或“哪个陈述正确”来排序。
- 同页允许返回多个片段，以保留相距较远的相互矛盾陈述。对重叠达到较短结果一半的窗口去重；这可能减少部分覆盖，不是完整冲突发现保证。
- 返回原始 source_ref、页码、start/end 与原文切片。v2 的 matched_terms/score 只描述实际返回的完整命中；输出被预算裁剪后重新计算。检索相关不等于引用正确，更不等于语义支持。

原有限制继续生效：最多 64 个明确来源、2000 页、200 万源字符；扫描超预算报错，不因已找到足够结果而提前忽略后续来源。limit 为 1–10，max_chars 为 256–8000，默认分别为 5 和 4000；整数不能用 bool 替代。两种方法都不搜索文件名、来源元数据、记忆、参考答案或其他任务。v2 的 truncated 保守表示匹配窗口有遗漏，包括去重，不表示遗漏窗口一定包含新事实。

## 公开的开发评测

材料位于 `benchmarks/inputs/retrieval-development/cases.json`：18 个合成案例、21 个手工声明的目标片段，覆盖参数、初值、单位、公式、补充材料、同页与跨来源冲突、澄清范围、符号边界、Unicode、缺失声明、无匹配及词汇不一致。

这些是本轮构造并使用的开发材料，**待独立审核，不是论文金标准、领域专家审核集或未见留出集**。原有独立评测集未用于本轮开发。评测器将材料和查询交给检索器，标注只用于检查输出。

指标与预算：每次最多 3 个结果、1200 个片段字符。完整覆盖要求某条结果包含目标片段的整个原文范围；相关结果要求与标注范围相交。引用另外检查来源白名单、原文切片和偏移。上下文同时报告片段字符及返回对象紧凑 JSON 字符，不将字符量当作 token 或费用。

| 指标 | lexical_v1 | passage_v2 |
|---|---:|---:|
| 完整覆盖目标片段 | 10/21 | 19/21 |
| 完整满足案例（含无匹配负例） | 7/18 | 16/18 |
| 正例平均倒数排名 | 0.412 | 0.706 |
| 不与标注相交的结果比例 | 50.0% | 31.0% |
| 返回片段字符总量 | 7151 | 2191 |
| 返回对象 JSON 字符总量 | 12266 | 8830 |

片段字符减少约 69%，返回 JSON 字符减少约 28%；新增多个片段也增加了元数据开销。这里的“无关”只相对于声明的标注，非标注上下文不一定没有科研价值。检索器没有解释矛盾、核实公式或判断哪条声明为真。

保留的两个失败：纯词汇方法无法命中没有共享词的“starting population”与 `N(t=0)` 对应关系；长段中的一条目标陈述在窗口边界被截断，虽含全部查询词却没有完整覆盖标注。必要时仍应读取原页。不为追求满分按案例新增同义词或特定数值规则；是否引入语义排序/embedding 应在更广、独立审核材料上判断。

## 实际验证

修改前完整回归 688 项通过，修改后完整回归 **715 项通过**。新旧检索、上下文与记忆的针对性组合 129 项通过；最终独立重跑新增检索测试 27 项通过。18 个基线案例的 v1 完整结果与修改前逐项相同，材料哈希也相同。

新增故障与边界覆盖来源隔离、非匹配页扫描预算、Unicode 偏移、最长查询词、符号子串误匹配、输出裁剪、重叠去重、同页冲突、方法冻结、旧任务回退及恢复前拒绝无效方法。这些是代码行为验证，不是模型自主表现。

另用脚本动作执行“片段检索 → 从返回片段选引文 → 草稿校验 → 真实 ODE → 结束”：4 次动作完成，衰减模型末值与解析解绝对误差约 2.37e-7，科学状态仍为 not_verified。首次演练因脚本缺少多进程入口保护失败，原脚本和部分产物保留；仅修正演练脚本后另存 v2 结果，未为重跑修改产品、预算或评分。该演练不是新的真实模型成功。

本轮未改善崩溃恢复、自动记忆候选、多 Agent 或 PDF 解析；这些继续按路线分轮推进。未重试此前等待外发授权的 c13/c18 在线回归，也没有新的自主 Agent 成功率结论。
