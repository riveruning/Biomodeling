# Agent 可靠性改进：调用恢复与来源冲突阻断

2026-10-17。本轮只优化开发项目，未读取、导入或运行 DSH 新制作的独立测试集。现有 10 个合成案例作为已经见过的开发回归材料，不用于宣称泛化优势。

## 已实现

### 有预算的调用恢复

- 格式错误、传输错误、HTTP 错误分别记录；认证及其他永久 HTTP 错误直接结束。
- JSON 格式错误请求模型重新回答；输出的整数长度及嵌套深度也有明确上限，不通过截断字符串、补括号或执行部分对象来修复输出。重复键、多个对象、非有限数字和错误 args 类型被拒绝；合法引文中的 Markdown 围栏可保留。
- 默认最多重试两次，每一次都消耗 `max_calls` 的总调用预算，与草稿结构修复分别计数；重试过程写入事件与检查点。
- 暂时性 HTTP/传输错误采用有上限的退避，遵守服务的 `Retry-After`。等待超过 30 秒时记录延期并结束当前交互，不提前继续请求。
- CLI 增加可选 `--json-mode`，只用于明确兼容的服务。默认仍关闭，不依赖服务强制 JSON 支持。
- 提示明确区分未知数值 `null` 与未知单位字符串 `unknown`，说明当前率规则模型不支持 `nonnegative=true` 约束，减少无效草稿。

### 来源冲突与执行门禁

- 对参与模型的明确命名声明检查缺值、重复数值冲突、时间速率单位冲突和明确未选定的 ODE 备选表达式。
- 同一量的等价秒/分/小时速率换算不视为冲突；模型符号区分大小写，例如 `k` 与 `K`。
- 保存 `source_review` 不可变产物及来源位置、原文、目标和待澄清问题。存在未解决问题时，草稿停止于 `awaiting_input`，没有可执行模型或模拟运行。
- 严格执行 API 在缓存查询与求解器启动前再次检查链接来源；对已链接的来源，手动构建模型或直接调用 API 也会执行此检查。没有可读来源不等于没有冲突，仍保留未知状态。有争议或反对关系的证据也会阻断严格执行。
- 仅显式、针对具体目标的作者澄清可解决对应问题。普通后续数值、无关目标的更正、要求忽略冲突的指令不能自动解除阻断。
- 未检测到冲突仍表示 `semantic_support=unknown`，不会自动升级为来源已被验证。

### 可见诊断

Agent 报告增加重试次数、失败类型、延期信息和待补充问题。等待输入的事件标明来自模型提问还是验证器阻断。

## 边界

严格复现模式与假设探索模式分别处理：前者遇到明确缺口或冲突必须澄清；后者仍可在授权的机制范围内提出带假设标记的模型，来源问题继续保留。

这是保守的显式声明检查，不是任意文献的语义理解系统。当前主要识别有明确符号和英文声明的情况，时间单位检查也不等于通用量纲推理。隐含矛盾、其他单位体系、复杂多实验上下文和任意语言仍需要独立审核与后续开发。

作者更正在这里仍然是给定材料中的声明，不是独立人类审核。真正的研究者回复落盘与原会话恢复尚未实现；本轮的“补全后成功”仍指新会话重新建模。

## 验证

新增 33 项针对性测试覆盖协议恢复、重试预算、服务冷却、严格解析、来源位置、等价单位、大小写、澄清作用范围及直接 API 防绕过。完整项目回归 **273 项通过**。

已有 18 份开发输入的确定性来源检查符合预期：八个不完整输入要求澄清，两个完整及八个明确澄清输入不因旧问题被阻断。该结果是规则检查，不是 LLM 评测成绩。

真实运行沿用旧案例、qwen3.8-chat、每例 8 次总调用、2 次草稿修复，新增最多 2 次预算内重试；JSON 模式关闭，调用串行且每次请求前间隔 5 秒。不改写模型答案，不覆盖原始评测。运行协议、代码指纹、原始响应及结果保存于 `artifacts/agent-reliability-fix-20261017/`。

| 配置 | 完整输入通过 | 缺口识别 | 无依据执行（越少越好） | 补全后通过 |
|---|---|---|---|---|
| 改进前，原串行开发记录 | 0/2 | 3/8 | 1/8 | 1/8 |
| 改进后，默认文本模式 | 2/2 | 8/8 | 0/8 | 7/8 |
| 改进后，可选 JSON 模式 | 2/2 | 8/8 | 0/8 | 8/8 |

以上是同一批已见开发材料的前后描述，不是独立留出集成绩或架构优势证明。两轮模型服务别名相同，调用时间不同；改动同时包含提示、错误恢复与来源门禁，不能把提升只归因于其中一项。

默认文本模式仍保留最后一例 unit_decay/clarified 的失败：三次连续非法动作 JSON 使它在重试上限后停止，未伪造成功。该轮总计观察到 8 次格式错误，实际进行了 7 次预算内重试，只有 1 例以协议失败结束。八个正确停止中，六个来自模型主动提问、两个来自验证器阻断。

可选 JSON 模式单独重新运行全部 18 份输入，先处理前述失败例，再按固定顺序处理其余输入；没有把默认模式的成功案例复制进去。它请求 `response_format={"type":"json_object"}`，当前 USTC 服务实际接受该参数。该轮格式错误观测数为 **1**，终止于格式错误的案例数为 **0**。默认模式原始结果保持不变。

该模式的一次协议重答来自合法 JSON 中的顶层 `question` 字段，动作字段没有符合约定；它被客户端拒绝后重新回答。这说明请求 JSON 语法约束不能替代动作结构校验。具体错误保存在 `json-mode-protocol-errors.json`。

JSON 模式约束与科学正确性分开解释：官方接口区分 JSON 语法与 JSON Schema 结构约束，客户端仍需验证动作、参数、来源及数值结果；当前服务的实测行为不能推广到任意兼容服务。[OpenAI 官方说明](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)

| 配置 | 模型调用总数 | 服务报告 token | 含节流的累计案例耗时（秒） |
|---|---|---|---|
| 默认文本模式 | 62 | 118651 | 851.8 |
| 可选 JSON 模式 | 59 | 113444 | 663.9 |

每个案例仍最多 8 次调用；时间含每次请求前的 5 秒节流，服务报告的 token 不等于美元成本。重试提升了默认模式的可完成性，也增加了开销；这些不是控制服务负载、缓存或重复随机种子的效率实验。

默认文本模式之后，补充了假设探索兼容性、不确定澄清、JSON 数值/深度上限和争议目标诊断的边界修复。默认模式的原始 18 份响应使用最终代码无网络重放，状态与调用次数完全一致，九份可执行轨迹通过数值参考；这不是额外的真实 LLM 试验。可选 JSON 模式实际使用最终代码完成整轮运行。两种代码指纹和响应记录分别保存，未在运行中换代码。

## 使用与后续

服务明确兼容时，可以在现有 Agent 命令后追加 `--json-mode`，例如：

```bash
.venv/bin/python -m biomodel_agent agent \
  --source benchmarks/inputs/reliability/decay/initial/source.txt \
  --experiment benchmarks/inputs/reliability/decay/initial/experiment.json \
  --store artifacts/my-agent-json \
  --base-url https://YOUR_PROVIDER/v1 --model YOUR_MODEL --json-mode
```

密钥仍由 `BIOMODEL_API_KEY` 环境变量提供。服务不支持 JSON 模式时不要开启；产品不会为兼容性擅自改写模型答案或隐藏额外请求。

复算无需外部模型：

```bash
.venv/bin/python benchmarks/development/score_agent_reliability_fix.py
.venv/bin/python benchmarks/development/score_agent_reliability_fix.py \
  --run-dir artifacts/agent-reliability-fix-20261017/live-json-mode
```

本轮完成调用恢复与显式来源门禁。下一项仍是真正的研究者回复落盘与会话恢复；现有补全试验使用新会话，不将它报告为恢复原会话成功。

DSH 新测试集未读取、未并入、未用于本轮调试。后续先独立审核，再冻结并评价最终配置；本轮结果只可作为回归改进证据。
