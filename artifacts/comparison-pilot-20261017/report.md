# 通用 Agent 与 BioModel Agent 小型开发评测

2026-10-17。已实际完成 3 个系统 × 3 个输入变体，共 9 次运行。没有在观察结果后修改产品、修正提交内容或重试挑选更好的答案。

## 本轮比较了什么

同一篇已用于开发的 Goodwin 论文片段构造三个条件：raw（公式是不可读图片）、assisted（辅助转录但缺初值）、complete（另行明确提供分析者选择的探索初值）。这是一个案例的三个变体，不是三篇独立论文，不是盲测。complete 是探索性模拟，不是原图严格复现。

| 系统 | 实际模型与运行方式 |
|---|---|
| 本项目 Agent | qwen3.8-chat；不改提示词与产品代码，原工具链，每组最多 8 次调用/2 次修复 |
| 通用 DSH | qwen3.8-chat；现有权限网关的文件工具模式，三组各新会话，不能自己运行 shell，交付独立 Python 后由评测器执行 |
| Codex CLI | 0.162.1，保留用户配置的 gpt-6.1-sol；临时独立工作目录，workspace-write 沙箱，使用原生文件/命令工具，三组各新会话 |

Codex 忽略额外用户配置以不加载项目 MCP，仅保留所选模型及既有原生登录。所有组使用相同源文本、采样协议和不补无依据初值的要求；通用系统不需要输出产品内部格式。评测程序、参考答案和先前结果没有提供给被测系统。

## 指标及实际覆盖

| 指标 | 本轮的判断方法 |
|---|---|
| 内容正确性 | 对 8 个参数、3 条方程、3 个初值逐项比较；方程用冻结探测点，非符号等价证明 |
| 来源支持 | 原文引用存在、唯一，并覆盖对应参考锚点；参考语义标注仍待独立人审 |
| 缺失信息处理 | 正确保留未知与无依据填值分开；额外符号另列，不把永远拒绝计为提取成功 |
| 可执行交付与数值结果 | 独立执行未修改的 Python 或产品模型；61 个采样点、固定尺度 10、最大缩放误差阈值 1e-3 |
| 效率与修复 | 墙钟时间、可取得的 usage、产品格式修复；本轮人工内容纠正均为 0 |
| 复算 | 通用程序在新目录无密钥环境运行；产品另用独立 CLI replay 检查 |

人工操作耗时、真实用户负担、完整单位语义、参数拟合、置信区间、机制发现及实验建议没有在本轮计分，不能声称已验证。

| biomodel | raw | 不适用 | 14/14 | 0 | 0 | 未模拟（信息不足） | 7.9 |

| biomodel | complete | 14/14 | 不适用 | 0 | 0 | 通过；1.58e-06 | 65.3 |
| dsh | raw | 不适用 | 14/14 | 0 | 4 | 未模拟（信息不足） | 67.5 |
| dsh | assisted | 11/11 | 3/3 | 0 | 0 | 未模拟（信息不足） | 60.4 |

| codex | raw | 不适用 | 14/14 | 0 | 0 | 未模拟（信息不足） | 70.8 |

数值误差不同主要受求解器与容差影响，三者均低于同一预设阈值；不能据误差数量级直接给 Agent 智力排序。信息不足条件下没有可执行模型是合理结果，不作模拟失败率。

## 逐轨迹复核发现

- 三组在缺初值条件下都匹配 11 项核心内容，并保留 3 项未知。安全停止并非我们的独有优势。
- 信息完整条件下，三个系统均匹配 14 项内容并交付通过数值检查的实现。我们的工具链在该探索条件下可以执行，但这一小案例没有显示优于通用 Agent。
- DSH 在 raw 中额外给出 alpha、beta、gamma、K 四个无来源参数名（值均为 null）。这些在 extra_targets 中单列，不能隐去，也不能泛化为所有 DSH 任务的错误率。
- DSH 的 raw 记录把工具显示的长行截断误认为源文件内容截断，并未完整读取该长行。所有源文件实际相同且完整。此为本轮配置/读取策略的局限，不能据此断言 DSH 本体能力不足。
- 我们的 assisted 提交发生 2 次格式修复，最后还有 nonnegative=true 与 rate-rule profile 不兼容问题；awaiting_input 不能解读为只差初值。complete 组经过 1 次修复后成功构建并运行。
- DSH 在 complete 说明中断言模型刚性，未经本轮独立验证；叙述正确性尚未全面量化。

## 资源与公平性限制

三者不是严格同预算：本项目有调用与修复上限；DSH 预算包含网关审批、轮询与文件交付开销；Codex 是不同底层模型并可自行执行命令。本轮运行还存在并发与服务延迟影响，墙钟时间只作观察。DSH usage 不可取得，不记为零；Codex usage 包含大量缓存输入，与 USTC 的 total_tokens 口径不同，不作直接费用比较。

每组只运行一次，一篇开发论文的三个变体不能估计普遍成功率或统计显著性。辅助文本已直接说明初值缺失，测的是明确缺失提示下的行为，不是自然论文中隐蔽缺失的发现能力。未进行统一用户协作与人工修正计时。

## 对产品定位的启示（讨论，不是开发指令）

目前不能把“会提取方程、引用来源、缺参会停下、能运行 ODE”单独当成已证实的竞争优势。后续值得检验的是更复杂案例中的语义错误识别、冲突材料处理、人工审核后的续跑和完整研究交付所需的人工工作量。
