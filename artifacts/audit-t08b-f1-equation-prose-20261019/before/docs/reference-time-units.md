# 结果与参考轨迹时间单位

2026-10-18（北京时间）。承接显式实验时间约束，本轮补齐模拟结果和参考轨迹的时钟标签，继续离线开发，没有外部模型请求。

## 行为变化

之前比较器仅检查数字时间网格与数值。两个相同的 [0, 1] 网格，即使一个表示分钟、另一个表示秒，也没有独立元数据可用于拒绝比较。

现在 SimulationResult 增加可选 `time_unit`，规范化规则与 ExperimentSpec 相同：second、minute、hour 及已支持别名；旧记录缺少字段时为 unknown。成功模拟沿用实验声明并已通过的时钟标签；SciPy 预测也返回该字段。实验未声明时，结果继续记为 unknown，不用模型单位名替用户补写实验协议。

参考结果可以使用完整 SimulationResult JSON，也可以使用带 times、values、scales 等字段的现有 CLI 简写。两种形式都保留 time_unit，不能因简写转换而把冲突单位丢掉。

```json
{
  "times": [0.0, 1.0],
  "values": {"x": [1.0, 0.670320046]},
  "time_unit": "minute",
  "scales": {"x": 1.0},
  "threshold": 0.001
}
```

## 比较规则

| 实际轨迹单位 | 参考单位 | 行为 |
|---|---|---|
| minute | min / minute | 检查原网格与数值，单位核对为 pass |
| minute | second | 拒绝，不自动换算或插值 |
| minute | unknown / 未声明 | 拒绝，不能假定未知单位与分钟一致 |
| unknown / 未声明 | minute | 拒绝，需明确实验与参考的同一时钟 |
| unknown | unknown | 保留旧数值比较口径，time_unit_status=unknown |

compare_series 同时支持结果对象和现有字典输入，输出 time_unit 与 time_unit_status。应用在缓存和求解前核对实验与参考标签，避免仅因某条缓存的数字吻合就通过。Agent 在首次调用模型前检查，并在恢复时、保存研究者回复前复查冻结的参考协议。

缓存输入与重放保留实验和参考的单位；比较报告显示标签及核验状态。恢复不能通过研究者回复改变被冻结的参考时钟。历史上若某个暂停点已带显式实验单位、却没有相应参考单位，新代码会明确拒绝继续该不完整比较协议，不静默改写旧任务；原记录仍可读取，需建立显式、相符的新任务。

## 验证

新增 29 项回归：结果 JSON/pickle 与旧字段省略、非法标签、对象/字典跨单位拒绝、未知单位边界、单位别名、模拟和独立预测的标签、缓存/求解前拒绝、带单位参考的真实执行与报告和重放、CLI 简写字段保留、模型调用前拒绝、冻结参考不进入模型上下文，以及旧不完整协议在恢复保存回复前阻断。

首轮针对性组合 95 项通过；补入两项恢复兼容性检查后，完整预验收 **431 项通过**，基线为 402 项。全量预验收沿用同字节存储测试副本以保持派生工作进程加载候选源码，原存储测试未改动。正确分钟衰减轨迹与解析参考核对通过。

这轮跨结果契约、数值比较、应用、Agent 与 CLI 保留同一个字段，连同模拟、预测和报告做同次验收，防止中间接口静默丢失单位。没有改写任何冻结评测结果或新增模型成绩。

源码快照、补丁、哈希、测试日志/XML 在 `artifacts/reference-time-units-20261018/`；安装后验证与旧任务的脚本恢复演练另存于同目录。脚本演练不是新的模型能力测量。

## 范围

单位标签是输入协议的声明，不是论文或研究者真实性认证；不进行自动换算、任意单位推理或物种量纲核验。历史双 unknown 的数值比较行为保持兼容，既有 passed_structured_reference 枚举仍只表达原有数值协议通过；它与 time_unit_status=unknown 同时出现时，不表示时间单位已核验。

本轮仅补时钟协议，不把数值一致自动升级为科学解释成立。真实模型修订验证仍等待此前的外发授权。
