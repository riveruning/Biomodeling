# T03b-1: recovery core (Codex acceptance contract)

Implement ONLY `src/biomodel_agent/recovery.py` (currently empty) and extend `invocations.py`. Agent integration is a separate dispatch. No shell, search, directory listing, tests, network or subagents. Read/write/edit explicitly listed paths only. Do not change storage or tests. Preserve all T03a invocation semantics and credential allowlist.

## Journal additions

1. `InvocationJournal.__init__(..., recovery=None, initial_refs=())`: optional JSON recovery metadata stored as execution payload key `recovery`, plus explicit initial refs in execution envelope. Existing callers continue working. Every NEW invocation reserved/terminal gets a positive integer `sequence` starting at 1 per execution; increment only after reservation put succeeds. Terminal shares its reservation's sequence. Do not link operations into a deep chain.
2. Classmethod `reopen(store, execution_ref, *, refs, calls, runs, next_sequence)` constructs an attached journal WITHOUT writes/new execution; callers must have passed diagnose + owner lock. Restore counters, refs and `_sequence=next_sequence-1`; next new reservation uses next_sequence. Validate execution/task kinds and count budgets. Keep methods `_terminal` usable by replay for pending read completion; add optional keyword `sequence` to `_terminal` if necessary.

## recovery.py APIs

`RecoveryBlocked(ValueError)`.

`implementation_fingerprint() -> str`: hash sorted package-relative names + bytes of all .py files under this module's package and runtime Python version plus installed numpy/scipy/python-libsbml/libroadrunner versions (importlib.metadata; deterministic unavailable marker). No credentials/environment dump. This is a conservative compatibility gate, not a proof of bitwise reproducibility.

`execution_owner(store, task_ref)` contextmanager: Linux `fcntl.flock(LOCK_EX|LOCK_NB)` on `<store.root>/.agent-owners/<task_ref>.lock`. Validate 64-hex ref and task kind before constructing path. Use fd with O_CLOEXEC/O_NOFOLLOW, mode 0600; retain file, never unlink it. Always unlock/close on BaseException. Competing process/thread raises RecoveryBlocked; OS termination releases lock. Unsupported platform refuses. Does not claim lease expiry or distributed ownership. Recovery diagnosis itself does not create/acquire locks.

`diagnose_execution(store, execution_ref) -> dict`: READ ONLY, never put, repair index or call tools/provider. Scan object files rather than relying on SQLite index (object may land before index write). Validate hash/schema/refs using store.get. Ignore temporary files; corruption must fail closed with useful code/reason. Return dict with:

- `execution_ref`, `task_ref`, `status`: ready / blocked / finished; `reasons`: list of stable strings; `operations`: ordered list of `{reserved_ref, terminal_ref (or None), reserved: payload, terminal: payload (or None)}`; `call_count`, `run_count`; `final_run_refs`; `adoptable_result_refs`; `recovery_refs` (prior agent_recovery records for this execution).
- Validate execution.version=1, task resume_version=1, max budgets equal, strict non-bool counts, execution recovery metadata `{version:1, implementation_sha256:<current>, source_refs:[...], restored:dict or None}`. Legacy missing recovery metadata stays blocked (report recoverable references without pretending a snapshot exists).
- Verify recovery source refs are actual sources, include task source refs and only parent checkpoint/clarification sources for resumed execution. `restored` must have the original initial counters matching execution base counts. Parent must be an awaiting_input agent_run for same task if provided; frozen initial restored refers to that parent's history + attributed reply. Do not trust task refs of another execution.
- Validate journal grouped by operation_id, contiguous unique sequences (never order by timestamp), exactly one reserved and at most one terminal, identical execution/name/sequence/counts/replay_class, terminal explicitly refs its own reservation. No missing/extra phases or non-JSON structures; kinds/classes must match REPLAY_CLASSES. Expected cumulative counts start from execution base counts and advance +1 per respond / scientific invocation; counts cannot refund, jump or exceed max.
- Missing terminal: only final operation allowed. `respond` => external_outcome_unknown blocked; scientific => scientific_outcome_unknown blocked; submit_draft => partial_artifacts_unknown blocked. A final reserved-only read_only may be safely re-executed under lock; status ready with operation flagged `retry_read_only`. Terminal error/interrupted remains blocked conservatively, even if retry class is read_only; do not infer no side effects or replay arbitrary exception text.
- Returned respond must contain JSON action text; returned submit_draft must contain replay-complete result dict (all keys except artifact) and model/draft refs bound in envelope if present. Actual artifact reconstructed later from model. Returned inspect_source has page_found; other reads have bounded JSON result dict. Returned run/run_study must have result_ref of kind run/hypothesis_study AND that ref in terminal envelope, with run reserve model/draft or study plan present/valid. Unknown/missing result fails closed. Expose verified actual result refs for adoption; never locate partial result by choosing latest result in store.
- Existing agent_run with execution_ref means finished: never continue it again, regardless of state (awaiting_input uses existing resume API). Ensure matching task_ref and refs. Return finished only with valid log; errors remain blocked.

`ReplayJournal(store, report)`:

- Attaches same execution with InvocationJournal.reopen; it is continuation, not a new branch. Replay returned operations from the initial execution state WITHOUT calling their callbacks or writing another reserved/terminal record. `.execution_ref`, `.refs`, `.calls`, `.runs` behave like Journal, with refs/counters advancing as old operations are consumed. Underlying live journal starts with full old counters and next sequence; all new work uses its normal budget reservation.
- `invoke(name, callback, *, details=None, summarize=None, result_refs=None)` checks next cached operation name AND exact JSON reservation details before consuming. Replay mismatch raises RecoveryBlocked before any new side effect. Deep-copy cached details. respond: parse response_json and expose `.last_usage` from stored usage (None for a new real respond). submit_draft: restore full cached result, add artifact=from_dict(ModelArtifact, store.get(model_ref)['payload']) or None. run/run_study returns verified result_ref. inspect_source re-read immutable source page using recorded args/page_found (pure, no callback). other reads return cached details. No duplicate tool/call budget.
- If the last operation is a safe reserved-only read, call callback once, write terminal using SAME reservation/operation_id/sequence (not a second reservation); error/interruption are journalled and reraised. Use provided summarize/result_refs; costs unchanged. Afterwards new invokes delegate to attached live journal and synchronize refs/counters.
- `assert_consumed()` refuses finalization if cached operations remain, preventing drift from silently discarding work. `.last_usage` applies to last respond only, not stored credentials.
