# 七个 Agent 方向的实现与缺口

本表区分已实现功能、固定流程/数值验证和真实模型能力证据。代码通过回归不等于 Agent 在未见科研任务上具有优势。

| 方向 | 当前已实现 | 主要缺口 / 下一步条件 |
|---|---|---|
| 架构 | 单个逻辑 Agent、模块化单体、受控计算进程，LLM 不决定验证是否通过 | 多 Agent 仍是待验证选项。应先用相同底层模型、相近预算做质量/成本对照，再决定是否增加角色 |
| Memory | 项目/模型/来源范围的持久记忆，更正/撤回，任务快照与恢复；本轮新增有界工作上下文、原历史留存和实际发送审计 | 尚无自动生成并审核记忆候选的流程；大规模索引、跨副本撤回同步和真实长任务行为评测未完成 |
| RAG | 授权材料内的关键词检索、精确原文偏移、确定性排序与扫描/输出预算；新增可选片段排序、冻结方法与18例合成开发对照 | 开发标注待独立审核；尚无语义检索/重排、多模态公式或开放文献搜索，长陈述边界与词汇差异仍有限 |
| Tool Use | 材料读取/检索、记忆召回、技能读取、草稿/引用校验、模拟，以及冻结的训练拟合/留出比较 | 拟合仍限已验证的 profile；更多工具应由真实案例需求驱动，不开放任意代码来绕过科学契约 |
| 工作流 | 追问、归属回复、暂停/恢复、版本与预算冻结、一次研究执行、完整事实报告；本轮新增容量拦截与恢复前预检 | 任意崩溃点自动恢复、跨分支全局费用/执行限额、较复杂的研究修改与失效传播仍有限 |
| Skill | 固定版本的 ODE 复现、澄清复核、受约束研究指引；目录随任务模式冻结，不改变权限或科学判据 | 仍为少量内置流程；可增加有独立科学案例验收的技能，不急于通用插件市场 |
| Evaluation | 完整数值/故障回归、解析解、研究恢复与原检查点演练；本轮新增上下文保留/字符量消融和错误负控制 | 尚缺专家审核的未见科研任务、相同底层模型的通用工具基线和真实模块消融。脚本动作不能替代这些证据 |

本轮选择补 Memory 的工作上下文与 Evaluation，因为之前只有持久化与续跑，而每次请求仍可能携带不断增长的全部历史。详见 [上下文预算](context-budget.md)；前两轮能力见 [记忆与检索](memory-and-retrieval.md) 和 [受约束研究工具](agent-study-tool.md)。

RAG 首轮已建立[检索开发基线与可选片段排序](passage-retrieval.md)，保留旧版默认与已见材料的开发属性。接下来应独立审核和扩展材料、检验未见输入，并逐步补工作流故障恢复；是否加入 embedding 应根据实测，而不是仅因存在可用框架。多 Agent 的收益需要真实对照支持，目前没有证据据此更换单 Agent 路线。

此前四次 c13/c18 USTC 在线回归仍待明确的材料外发授权，未用新的工具改道重试。当前离线开发没有更新原冻结版模型成绩或把已见材料当作新留出集。
