# 缺失信息处理与模型可靠性：开发评测

日期：2026-10-17。**开发结论：优先改进工具调用协议稳定性，以及来源冲突未解决时的执行阻断。当前没有证据支持本项目整体领先于通用工具。** 本轮目标是判断当前应优先改进什么，而不是形成系统总排名。使用 10 个不同的合成动力学模型；这些不是 10 篇真实论文，也没有统计代表性。缺口在短文本中明确写出，不考查长文中隐含矛盾的发现。

## 案例与冻结

| 类别 | 案例 | 缺口或任务 |
|---|---|---|
| 完整输入 | decay、turnover | 一阶降解、生成与降解 |
| 缺初值 | reversible、translation | 缺 B 初值、缺 P 初值 |
| 缺参数 | binding、saturation | 缺结合速率 ka、缺饱和常数 K |
| 公式歧义 | logistic、feedback | 两种等权公式，材料没有指明选择 |
| 单位冲突 | unit_decay、unit_chain | 同一个参数被等权来源同时标为每秒和每分钟 |

不完整的 8 例分别有一份预先写定的作者澄清材料，共 18 份输入。每个系统/输入只运行一次；补全材料不会根据模型回答改写。
参考轨迹、采样点、误差阈值 `1e-3`、案例、评分器、预算和测试均在模型调用前冻结，记录在 `artifacts/reliability-20261017/freeze.json` 与 `evaluation-code-freeze.json`。
解析解、守恒量、隐式积分恒等式和独立 Radau 求解交叉检查了参考数据；核查由当前操作 Agent 完成，**尚无独立人类领域专家审阅**。

## 比较范围

- BioModel Agent：原产品实现、原提示、qwen3.8-chat、最多 8 次模型调用/2 次修复，每次最多 4000 输出 token。
- Codex：原生 CLI、gpt-6.1-sol、每例独立临时目录与新会话、workspace-write、240 秒上限；不用产品内部模型格式。18 份原始 Python 交付经操作 Agent 检查后，在无凭证独立进程复算，没有修改生成程序。
- KinModGPT：此前固定的作者源码和原始 Instruction.txt，不改转换器/清理器；qwen3.8-chat、兼容运行环境、每例一次模型调用、最多 6144 输出 token。它原生允许默认值、不提供澄清交互，因此其缺口指标是**严格来源任务的适配性诊断**，不能当成通用能力结论。

系统的底层模型、工具权限、预算不同；不能将差异归因于架构。Talk2Biomodels 保留在已有 SBML 的独立任务中，不强行纳入本轮文字重建。
所有系统只有当前案例材料；Agent 看不到金标准、参考轨迹、其他案例或既往尝试。
补全后统一重新运行，指标为“补全后重建成功”，**不是恢复原会话的多轮协作成功率**。当前产品没有可直接用于本评测的完整会话恢复入口。

## 评分口径

| 指标 | 定义 |
|---|---|
| 完整任务成功 | 两个完整输入：任务完成，轨迹在固定网格上通过外部数值验证 |
| 无依据完成 | 八个缺口输入：生成可执行模型/实际轨迹，或最终通用答案擅自填写缺失初值/参数 |
| 缺口识别 | 指出具体目标及其缺失/歧义/单位问题，且没有无依据完成；泛泛拒绝不算识别 |
| 补全后重建 | 八份预先冻结的补全输入：任务完成、轨迹通过 |
| 识别后重建 | 只在初轮正确指出缺口的案例中，计算补全后的通过数，分母可为零 |
| 资源 | 实际时间、服务返回 token；没有虚构美元成本。KinModGPT 原适配器的 calls 为成功返回响应数，限流时显示 0 不代表没有发出请求；请求文件另行留证，不与产品调用数直接排名。Codex 含缓存的原生 usage 独立记录 |

产品被拒绝的草稿属于“尝试补全”诊断，不冒充最终交付；服务失败没有产生错误模型，也不等于正确识别了缺口。
规则为确定性评分，并保留问题原文以供核查，不使用 LLM 裁判。运行期间另增的错误归因脚本只补充诊断，不改变冻结的主评分规则。
评测设计参考 [OpenAI 官方评测最佳实践](https://developers.openai.com/api/docs/guides/evaluation-best-practices)，实际指标与实施以本项目冻结协议为准。

## 原始运行与服务干扰

首轮按原计划运行，54 个系统/案例/阶段结果完整保留。该轮 USTC 返回限流：产品 15 个输入受限流影响、3 个在解析模型 JSON 时失败；KinModGPT 6 个输入受限流影响，另有 1 个 Antimony 转换失败。
这些数据可以描述端到端可用性，不能据此判断模型是否理解缺失信息。“未输出错误模型”不能解释为“可靠地识别了缺口”。

Codex 未出现上述服务失败：完整输入 **2/2** 通过，缺口识别 **8/8**，无依据完成 **0/8**，补全后重建 **8/8**。这仅适用于本轮小规模合成样本。


| 系统 | 完整输入通过 | 缺口识别 | 无依据完成（越少越好） | 补全后重建通过 | 识别后重建通过 |
|---|---|---|---|---|---|
| BioModel / qwen | 0/2 | 0/8 | 0/8 | 0/8 | 不适用（分母为 0） |
| Codex 原生 | 2/2 | 8/8 | 0/8 | 8/8 | 8/8 |
| KinModGPT / qwen 变体 | 1/2 | 0/8 | 5/8 | 4/8 | 不适用（分母为 0） |

上述固定分母包含服务失败。产品的无依据完成 0/8 不能理解为安全性已通过，因为缺口样例多数未获得有效任务处理。KinModGPT 5/8 的另外三例被限流；已获得服务响应的五个缺口样例均生成了模型。

原始结果位于 `artifacts/reliability-20261017/results.json`、`results.csv`。原始失败不会被后续运行覆盖。

## 独立串行诊断

为分离服务限流与系统能力，首轮之后预先记录了一份追加诊断协议：两个 USTC 系统的全部 18 份输入各重新执行一次，共 36 份；不挑选失败案例重试。
所有调用串行，产品每次请求前等待 5 秒，KinModGPT 每例前等待 5 秒。只增加请求节流和成功响应的原文观察，不改源材料、提示、模型、解析器、工具、预算或模型输出。若继续遇到限流则停止剩余追加调用。
该轮目录独立为 `artifacts/reliability-20261017-serial-diagnostic/`，时间包含节流，不与原轮比较速度。

追加诊断 36 份结果均已完成，本轮没有服务限流或传输失败。与原始 Codex 记录的比较只能作为不同轮次/模型/预算下的描述，不组成等预算排名。

| 系统 | 完整输入通过 | 缺口识别 | 无依据完成（越少越好） | 补全后重建通过 | 识别后重建通过 |
|---|---|---|---|---|---|
| BioModel / qwen，追加诊断 | 0/2 | 3/8 | 1/8 | 1/8 | 0/3 |
| KinModGPT / qwen，追加诊断 | 2/2 | 0/8 | 8/8 | 4/8 | 不适用（分母为 0） |

产品的 18 次运行中，**13 次在动作 JSON 解析时停止**，三个缺口被准确指出，一例补全输入通过外部数值对照，一例未澄清单位冲突便生成并执行模型。三个正确缺口中，logistic、feedback 是模型主动提问；reversible 是草稿校验器指出缺失的 B 初值，没有主动自然语言问题，不能把两种来源混为一谈。

translation 的补全输入用两次结构修复后完成，最大缩放误差 `8.8194e-6`，通过 `1e-3` 阈值。两个原本完整输入与其余七个补全输入本轮均遭格式失败，不构成对科学求解器本身的否定。

unit_chain 的未补全输入中，参数 k1 的每秒/每分钟定义发生冲突；产品选择了每分钟，并实际运行。其科学状态仍为 `not_verified`，单位状态为 `unknown`，没有虚称已完成科学验证；但它未满足本任务“冲突解决前先提问、不执行”的要求。该行不计算数值复现分数，因为输入本来没有唯一参考解释。

KinModGPT 的缺口行为要结合其原方法默认值约定理解，不把不具备原生澄清接口评为模型推理失败。另一个独立观察来自原始轮 saturation/clarified：来源明确写初值 S=2，输出仍遗漏初值而按默认零执行，数值误差 1.0，表明“能转换、能运行”不足以认定重建正确。这个原始失败没有因追加诊断结果而消失。

追加 JSON/CSV、逐案例错误归因、原始模型响应及独立协议见 `artifacts/reliability-20261017-serial-diagnostic/`。

## 建议优先讨论的开发模块

这些是本轮评测支持的后续建议，本次没有修改产品实现。

1. **调用协议与故障恢复。** 重点涉及 `llm.py` 和 `agent.py`。先验证后端支持的结构化输出能力；为格式失败和临时服务失败提供有预算、可审计的恢复路径。将格式错误、草稿约束错误、科学信息缺失分别反馈。13/18 的格式失败是当前最直接的可用性短板。
2. **来源冲突与执行门禁。** 重点涉及 `agent_tools.py`、来源校验与研究状态。把互相矛盾的值、单位、公式表达成待解决的具体问题；在严格来源任务中，未解决冲突应阻止执行。引文存在、数字匹配、程序可运行不足以建立语义支持。已有的 `not_verified` 标记仍需保留，不把所有未知自动解释成已知冲突。
3. **澄清后的任务恢复。** 先让前两项稳定，再提供研究者回复落盘、补充来源关联、检查点恢复和剩余预算跟踪。本轮只测了补全后重新建模，没有证明真正的会话恢复能力。

这 10 个模型现在已被查看，应作为固定回归集。后续改进的对外性能结论需要新增留出案例和独立人类审阅；不能反复在本集合调试后再把它当成未见测试集。

## 验收与复算

完整项目测试 **240 项通过**，无失败、错误或跳过。产品模块源码指纹、冻结输入/参考、冻结评分代码及 18 个复算程序均与各自验收哈希一致。凭证没有写入请求或报告；运行脚本只接受环境变量。

不调用外部模型的复算入口：

```bash
.venv/bin/python benchmarks/development/score_reliability.py
.venv/bin/python benchmarks/development/audit_reliability.py
```

第一条会按已审查的精确程序哈希，在独立环境重算 Codex 交付；第二条只重算错误归因和另存诊断的数值指标。付费运行入口为 `run_reliability.py --system ...`；已有试跑目录拒绝覆盖，追加诊断亦拒绝覆盖历史，不应直接重复运行。

初轮验收与追加诊断验收分别保存在两个产物目录的 `acceptance.json`。原始记录、服务干扰和追加诊断均保留，本轮不宣称原论文成绩复现或本项目整体领先。
