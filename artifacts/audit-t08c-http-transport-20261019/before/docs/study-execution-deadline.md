# 统一研究入口与科学计算总期限（T04）

任务来自[优化队列](optimization-backlog.md)。本轮由用户明确要求 Codex 独立实现、审查与验收，没有再派发 DSH 任务。继续采用单 Agent 与确定性工具，不涉及外部模型或独立评测材料。

## 已复现的问题

旧 `hypothesis` 命令直接调用研究内核，而 `study-run` 和 Agent 使用冻结计划适配层。内核不论是否全部拟合失败都保存 `status=completed`；旧命令据此返回成功。适配层只检查是否至少有一个拟合/交叉检查可用，不能阻断留出预测失败或部分候选计算缺失。

另有两处预算缺口：拟合预检在主进程实际求解 ODE，随后才启动受超时约束的优化器；拟合后的留出预测与干预预测也在主进程直接执行。单个拟合超时不等于整个研究有期限。

实施前独立基线15项中7失败、8通过；失败覆盖上述入口、计算完成判据与预测预算缺失。原始输出保存在[T04验收目录](../artifacts/audit-t04-study-execution-20261019/)。

## 共用执行层与完成判据

`hypothesis` 现在先冻结计划，再走与 `study-run` 和 Agent 相同的 `studies.execute_study`；科学内核仍是 `hypotheses.run_hypothesis_study`。两条CLI提供相同的候选、起点、种子、迭代上限、拟合上限、总期限和排序阈值设置。旧命令默认单次拟合上限由90秒统一为30秒；可以显式指定，冻结计划每次拟合仍最多90秒。

共用 `hypotheses.study_verdict` 从实际阶段、有限数值、交叉检查及期限记录导出结果；内核、计划结果摘要、命令行、研究报告和 Agent 的完成判断使用该判据，不用已有 `status` / `completion_eligible` 成功字符串覆盖失败事实。

| 状态 | 含义 |
|---|---|
| completed | 所选候选的必要计算完成；允许结论为无合适候选或不可区分 |
| timed_out | 总期限或某个必要计算阶段超时；保留已经保存的事实 |
| incomplete | 存在可用的拟合/交叉检查，但其他必要计算未完成 |
| failed | 没有可用候选计算 |

每个候选记录建模、拟合、交叉检查、训练评分、留出评分、适用的实验建议阶段状态。交叉检查同时验证采样长度、时间网格和有限误差。任一必要计算缺失时，不宣称确定赢家，不把计算失败写成“所有模型被数据否定”，建议预测差异也保留为None。

有效的科学负结果保持区分：若拟合、交叉检查和预测真实完成，但训练/留出误差不满足冻结门槛，研究仍可完成，排序为 `none_adequate`、无赢家。所有这类候选比较的科学状态仍为 `not_verified`，不是生物机制证明。

## 总期限如何生效

新计划为 `schema_version=2 / adaptation_study_v2`，显式冻结 `total_timeout_s`，默认300秒、最多600秒。原 `timeout_s` 保留为每个候选的拟合上限。一个单调时钟从科学研究工具入口开始，覆盖候选建模、拟合、交叉检查、留出预测、干预预测和比较；阶段之间、候选之间不重置。

每次调用最多得到剩余时间。交叉检查与单次预测另有30秒上限，拟合使用冻结的每次上限；实际分配取二者较小值。阶段前后检查时间，记录候选、阶段、分配秒数、耗时与错误类型；已经耗尽预算时不再启动后续计算。结果另保留总预算来源、耗时及是否耗尽。

拟合预检现在只做静态模型、映射、数据和时间单位检查，不在主进程积分。拟合CPU与研究内预测CPU分别在可终止的 spawned worker 中执行；等待也计入预算。worker超时、无结果退出或主进程收到中断时，执行终止与回收，不留下继续计算的子进程。原无 `timeout_s` 的独立 `fitting.predict` API 保持原行为，研究入口明确使用受限调用。

此期限约束一次研究工具的科学工作。此前的 LLM 讨论、研究者等待、最终回复与恢复审计写入不计入该科学预算，仍遵守原各请求和调用次数限制。静态验证、不可中断的本地文件写入及进程回收可能增加墙钟开销；这不是硬实时或操作系统断电保证。

## 兼容与中断恢复

旧v1计划按其原规范精确验证并保持不可变；本轮保存了修改前生成的真实v1负载，确认没有猜测重建。执行旧计划时明确声明 `legacy_execution_default` 的300秒预算，在计划摘要与新结果中说明来源，不把新字段回写成原计划内容。

旧研究产物的原始数值、状态和历史仍可读取，不覆盖旧对象。若旧产物缺少必要阶段/预算证据，当前完成判据保守拒绝重新宣称计算已完成；既有 Agent 记录的历史状态不会被回写。源码变化也继续受 T03b 的恢复指纹兼容检查约束，不绕过版本门槛迁移旧故障记录。

[T03b受控恢复](controlled-recovery.md)的所有者锁、一次科学调用和已返回结果认领规则保留。研究超时也会返回实际保存的研究产物；在结果返回后崩溃，恢复复用同一个引用及其原预算事实，不重拟合、不重新分配一个科学期限。工具结果未知时仍阻断，不从部分产物中猜测最新结果。

## 实际验证

首轮111项检查通过。扩展31项独立验收覆盖同一冻结计划的三个入口、有效负结果、预测失败、跨阶段与跨候选预算、旧v1兼容、worker超时/退出/中断回收，以及超时研究的结果认领。最终完整回归926项通过，186.94秒，无失败、错误或跳过；原有测试文件保持不变。命令、源码哈希及实际结果见[验收记录](../artifacts/audit-t04-study-execution-20261019/acceptance.json)。

可复查的[实际科学产物](../artifacts/audit-t04-study-execution-20261019/scientific-results.json)包括：

- 同一正例三个入口都拟合得到约 `k=2、d=1`，留出 scaled RMSE 约 `3.89e-10`，排序一致。
- 同一有效负例三个入口都完成计算，留出 scaled RMSE 约 `97.85`，均无赢家；没有伪装成计算失败。
- 实际极短科学期限在建模阶段耗尽，保存 `timed_out` 产物，未启动拟合；随后故障恢复沿用同一结果，拟合产物数量保持0，没有遗留数值子进程。预算分配到拟合、交叉检查和预测的负控制另由受控时钟测试验证。

这些是离线脚本动作、真实确定性计算与故障验证，不是新的真实模型科研能力成绩。没有读取独立留出集，也没有发送 c13/c18 材料或重试已被拒绝的在线回归。
