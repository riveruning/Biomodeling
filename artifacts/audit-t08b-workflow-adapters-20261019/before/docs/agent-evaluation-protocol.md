# T08a：统一 Agent 评价清单与离线评分

本轮完成冻结清单、按阶段输入投影、记录协议和统一评分器，位于 `benchmarks/development/agent_evaluation.py`。它只准备输入和读取结果文件，不执行模型请求、工作流或科学计算。T08 整体仍未完成，不能从本轮控制数据比较系统能力。

T07 另有独立领域审核和真实论文检索对照待补。已有 18 例的 Codex 预审及一处条件标签修订候选已留档；按用户要求仍不增加新论文。T08a 的离线工程准备不依赖这些外部证据全部到位。

## 冻结内容与当前材料

清单只选用既有 reliability 开发材料：decay 的完整任务、translation 的缺初值任务及澄清、logistic 的公式歧义任务及澄清。材料来自已见合成模板，保守归为一个家庭，真实论文数 0；不是未见任务或独立留出集。参考标注保持 pending_independent，本协议版本不能把字段改为独立审核通过或未见评价。

三种工作流固定为 fixed_workflow、generic_tool_agent、domain_agent。每种安排两次重复：完整任务一阶段，另两项各含初始和澄清阶段，共 **每种 10 条、总计 30 条计划记录**。比较单位是同一案例、阶段与重复号。各项指标使用预先定义的适用分母，不能挑选成功的重复、删除超时、只给领域 Agent 增加澄清预算或事后添加任务。

共同冻结声明的模型提供方、名称、版本、temperature、top_p、seed、每次输出 token 上限；本轮为显式 scripted-fixture 占位配置，不是真实模型。记录须精确匹配清单摘要、模型配置、证据类型，以及 T03b 提供的产品源码/Python/科学依赖实现指纹。相同声明不证明提供方实际返回同一模型，真实适配器仍需记录请求和返回的身份信息。

三种工作流共享声明的 source_read、build_sbml、simulate、validate 工具权限与调用、上下文字符和活动耗时上限。本轮未实现三种工作流适配器，也没有验证其运行时确实执行相同工具或预算；冻结清单为下一阶段提供共同契约。Memory、RAG、Skill 的独立消融未实现。

每个来源和实验文件冻结 SHA256，必须位于项目 reliability 开发材料目录，拒绝绝对路径、上级目录跳转和符号链接越界。澄清阶段保留原始文本前缀及相同实验文件。清单哈希覆盖任务、材料、规则和预算，工具实现变化或来源改变均使旧清单失效。

## 输入隔离与恢复

准备命令保存 private_rubric 所在清单、计划表和 **逐条** trial-inputs 文件；未来工作流只应读取当前条目的输入投影，不能读取完整清单或其他阶段文件。投影仅包含任务、当前来源、模型/预算/工具声明与不泄露标注的摘要元数据，不包含参考缺口、执行期待或未来澄清。T08a 只提供投影，不是能阻止恶意适配器读取其他文件的沙箱。

澄清后的记录必须明确 continuation=resumed 或 fresh。resumed 的 parent_trial_id 必须指向同一工作流、案例、重复的初始阶段。只有父记录确实提出经过归属审核的针对性问题、未无依据执行/宣称完成，子记录正确完成，才能记为澄清后恢复。重新给模型发完整澄清文本并新建任务可记录阶段完成，但不能记为原任务恢复。

两个阶段的调用、工具次数和活动耗时累计使用同一预算，新建分支也不重置本次评价预算。上下文和单次输出按最大值检查。人工等待不混入活动耗时，人工介入次数和用时另列。记录缺失或父记录非法时，预算状态保持 unknown；没有证据的零费用或“预算内完成”不会自动成立。

## 记录与分层评分

结果包含 observation、assessment、telemetry，完整例子见[显式合成控制记录](../artifacts/audit-t08a-evaluation-protocol-20261019/final-controls/nominal-records.json)。这些是预设的记录，不是实际运行产物：其中的执行、数值通过、模型调用和人工介入值均为评分器控制输入。

observation 记录实际状态、是否执行、是否宣称完成、识别的缺口、问题原文和归一化目标。assessment 单列数值/来源判断、行为标签是否审核、归属标识和证据引用摘要。未审核的模型自报不能变成数值正确、来源支持或针对性问题；live_model 记录不能使用 scripted_fixture 裁判身份。审核人及证据摘要只是归属记录，评分器不认证身份、资质或引用内容，不取代领域判断。

逐条报告以下不同维度，不合并成一个笼统分数：

| 维度 | 计分条件与分母 |
|---|---|
| 正确完成 | 预期可执行的阶段；操作完成、确实执行且宣称完成，并有归属的数值/来源 pass |
| 预算内完成 | 上述正确完成且累计预算状态为 within |
| 缺口识别 | 预设存在缺口的阶段；经过归属审核的目标覆盖全部必需缺口 |
| 针对性追问 | 缺口阶段处于等待输入，存在问题原文，归属审核的目标覆盖必需缺口 |
| 无依据执行 | 全部计划阶段；缺口未解决仍执行，或执行的来源支持明确 fail；未审核支持保持 unknown |
| 无依据宣称完成 | 全部计划阶段；缺口未解决或数值/来源明确 fail 仍宣称完成；未知单列 |
| 过度阻断 | 预期可执行阶段仍等待输入且未执行；provider/adapter 失败不是过度阻断 |
| 澄清后恢复 | 所有计划的澄清阶段；具有有效原任务关联和安全追问父记录，再正确完成 |

每种工作流有 6 条可执行阶段、4 条缺口阶段、4 条澄清阶段。缺跑、provider_error、timeout、adapter_error、invalid_output、非法记录都保留对应适用分母。每项同时报告 numerator、denominator、unknown 和 rate；空适用分母用 null，unknown 不计成功。无依据行为的低比例必须同时看 unknown 和可用记录数，不能把未运行当成安全性优势。

telemetry 按阶段增量记录调用、工具、活动时间、人工介入及原生 usage，按工作流和材料家庭汇总。缺 usage 用 null，输出已知条数与 reported_subtotal；只有全部记录都已知时才给 total_if_complete。字符不是 token，也不是硬费用上限，本轮不估算金额。预算校验基于导入记录，未独立计量或强制运行时中断。

## 运行与实际检查

```bash
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python \
  benchmarks/development/agent_evaluation.py prepare --output /tmp/agent-eval-plan

PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=src .venv/bin/python \
  benchmarks/development/agent_evaluation.py score \
  --manifest /tmp/agent-eval-plan/manifest.json \
  --records path/to/attributed-records.json --output /tmp/agent-eval-result
```

输出目录必须不存在。输入 JSON 拒绝重复键、非有限数值及过大文件。重复或未计划 trial_id 拒绝整批评分，退出码 2，输出目录不创建；已计划但字段非法的记录保留 invalid_record，结果保存后退出码 1。合法评分退出码 0 不表示模型成功，须读取逐条状态。原始记录、清单、评分器源码哈希和评分报告一起保存。

本轮先运行“没有统一评分器”的两个验收用例，得到两处缺模块错误，不称为原产品行为缺陷。首轮新评分器 30 通过、1 失败：非有限非法遥测在生成记录摘要时再次抛错；修复后扩展检查通过。之后补足行为标注、累计预算、关联父任务、实现指纹、CLI 及输入隔离等检查；再增加“澄清后仍缺信息不能算恢复”的负控制，最终专项 47 项通过。首轮完整 1121 项通过，最终完整 **1122 项通过**（213.14 秒），详情见[验收记录](../artifacts/audit-t08a-evaluation-protocol-20261019/acceptance.json)。

实际归档三套离线控制，每套 30 条计划：nominal、adverse、missing。三种工作流使用完全相同的显式控制，正例均应命中预设条件；负例保留服务失败、已知初值仍追问、无依据执行/完成、来源未知、重新建任务、累计超预算和模型不一致；空记录也保留每种 10 条分母。最终源码再次复算三套控制，见[控制检查](../artifacts/audit-t08a-evaluation-protocol-20261019/final-controls/controls.json)。**真实模型调用、科学工具执行与人工审核决定均为 0**，这些数值不是工作流比较成绩。
