# 显式实验时间单位约束

2026-10-18（北京时间）。本轮补齐实验时间协议，继续离线开发；没有调用外部模型或修改原冻结评测。

## 解决的问题

之前的 ExperimentSpec 只有数字时间点。即使材料说的是分钟，接口也无法独立声明这些数字属于分钟。若模型错误地声明秒，求解器仍可能交付一条形式正确、实际时间尺度不同的轨迹。

现在可在实验 JSON 中声明 `time_unit`：

```json
{
  "times": [0.0, 0.5, 1.0],
  "time_unit": "minute"
}
```

支持 second、minute、hour 及 s/sec、min、h/hr 等常用英文别名，保存时规范成标准名称。省略字段的旧输入保持 `unknown`；空值、空字符串、维度错误和未支持单位明确拒绝。采样点、初值、参数覆盖和输入分段均不自动改写。

按 SBML 规定，模型的 timeUnits 是全局时间基准，反应和速率规则使用该基准；缺少 timeUnits 不等于默认秒。[libSBML Model 官方说明](https://sbml.org/software/libsbml/5.18.0/docs/formatted/c-api/class_model__t.html)

## 执行与恢复

- 直接模拟在启动工作进程前检查。显式实验单位与模型不同，返回 failed 和 experiment_time_unit 检查；不启动求解器。
- 应用接口在写入冻结输入及查询缓存前检查，避免缓存绕过。通过后将实验单位写入冻结输入与检查结果；规范化的 min/minute 可以复用同一输入缓存，重放仍使用冻结单位。
- 拟合预测和训练预检使用同一检查，错误时间协议不进入积分或优化工作进程。模型时间尺度只在编译器初始化时解析，避免每次残差评估重复解析 SBML。
- Agent 的实验摘要向模型展示该单位。错误草稿时间基准返回 invalid，在既有调用与修订预算内修正；真正执行前仍由应用与求解层复查。恢复任务继承原实验时间协议，补充回复不能改变被冻结的时间单位。

旧输入未声明实验单位时仍可按原流程执行，但新增检查显示 unknown，不把未检查的时间一致性标成通过。该兼容行为不证明来源或时间单位正确。

## 有限的单位解析范围

检查使用模型实际的 SBML 时间定义，不相信 unit ID 的名字。例如，一个叫 minute 但实际 multiplier=3600 的定义，不会当作 60 秒。当前识别内置 second，或由单个 second 单元组成、指数为 1、无偏移、正且有限的 multiplier 与十进制 scale 的定义。[libSBML Unit 官方说明](https://sbml.org/software/libsbml/5.18.0/docs/formatted/c-api/class_unit__t.html)

未声明、复合或当前不能解析的模型时间定义，遇到显式实验单位时会阻断并说明无法核对，不猜测默认单位。这里没有实现任意单位系统、完整量纲分析、速率参数单位核验或自动的时间/参数换算；也没有新增参考轨迹单位协议。

## 验证与兼容性

新增 38 项针对性测试，覆盖 JSON/别名/不可变与 pickle、旧输入省略字段、生成模型与自定义单位定义、名称误导、非物理尺度、模拟启动前阻断、缓存查询前阻断、真实分钟轨迹、缓存和重放、拟合与优化入口、Agent 预算内修正及恢复时协议冻结，以及 CLI 的明确错误。

完整回归：**402 项通过**，修改前为 364 项。正确分钟衰减模型的实际模拟与解析解 exp(-0.4*t) 核对；匹配单位的独立 SciPy 预测也通过解析参考。这是软件与数值协议验证，不是新的 LLM 或论文复现成绩。

本功能跨数据契约、Agent、应用、模拟与拟合共用一个检查模块，作为同一次原子改动验收，避免某条运行路径遗漏约束。无需新依赖。

首次全套预验收曾因存储测试向 sys.path 插入项目旧源码路径，使新建的拟合子进程读到旧版契约而失败；父进程读到的是候选版本。最终预验收以字节相同的该测试副本保持子进程导入候选源码，原测试文件未改动。最初的一条 CLI 测试调用也曾把位置参数错写为 --sbml，已按实际 CLI 修正。上述初始日志与最终全量日志/XML均保留，不把测试路径问题报告为产品的单位换算能力。

示例 Python 接口：

```python
experiment = ExperimentSpec((0.0, 0.5, 1.0), time_unit='min')
```

用户应根据材料明确声明实验时钟，并使模型的时间基准与之相符；该字段不会自动验证材料中的参数单位或生物学解释。
