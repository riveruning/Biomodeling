# 实现交接与验收

状态：原始 v0.1 开发提案；2026-10-14。现已完成业务原型、环境安装与有限基准验收，见 [实际实现范围](v0.1.md) 和 [验收证据](acceptance-v0.1.md)。本文件保留开发顺序与后续研究计划，不代表所列评测均已完成。

## 1. 给实现者的交接摘要

建议按以下要求启动实现：

> 阅读三份设计文档，先核对目标模型所需语义和候选科学库能否安装运行。先完成一个不依赖 LLM 的垂直闭环：结构化模型输入 → 校验 → 模拟 → 数值诊断 → 与可信参考比较 → 保存研究包 → 在干净环境重跑。随后接入文献提取、来源映射和受约束的 Agent。课程交付需同时包含 A 和一个受约束的 B 闭环。不要先选复杂 Agent 框架，不实现多 Agent、任意代码执行、通用 PDE 或知识图谱平台。对影响科学语义的设计变更记录原因、替代方案与验证方法。

GPT-6 Sol、DSH、Codex 等开发工具可以承担规划、实现和审查。上述名称不应出现在产品核心业务接口中。开发工具的组织方式也不要求复刻为产品 Agent 角色。

技术实现细节可由实现者在契约范围内决定；科学范围变更、削弱检查、改变基准定义或新增无依据假设需要显式记录并交项目所有者审阅。常规修复和已授权范围的测试不需要逐次请求确认。

## 2. 推荐工程形态

建议 Python 单仓库。具体解释器、科学库与类型库版本由兼容性验证后锁定，不追求所有依赖使用最新版本。

拟议目录如下，当前不要求先创建所有空模块：

```text
src/biomodel_agent/
  domain/           # 对象、引用、不变量与规则，不依赖供应商 SDK
  application/      # 模型构建、模拟、比较等用例，CLI/Agent 共用
  adapters/
    scientific/     # libSBML、libRoadRunner，后续其他后端
    documents/      # 材料提取和位置映射
    llm/            # 供应商适配
    storage/        # 文件与 SQLite
  orchestration/    # 状态、预算、策略、断点恢复
  interfaces/       # CLI、Notebook 入口，未来 UI
tests/
  contracts/        # 科学语义与接口不变量
  scientific/       # 已知解、收敛、故障和独立参考
  integration/      # 研究包闭环及恢复
benchmarks/
  manifests/        # 公开任务定义、目标和材料清单
  inputs/           # 允许系统读取的输入
  development/      # 开发用参考及评测脚本
docs/
```

保留测试的参考答案放在独立评测工作区或进程，仅评测器可访问；不要只放在同一可读目录下并要求 Agent “不要看”。初期采用资料包模式，不需要自由浏览整个互联网。

运行产物与大文件放在工作目录或配置的数据目录中。原始材料能否再分发按各自许可处理；必要时仓库保存获取说明、版本和校验值，而不是完整论文。

## 3. 开发切片与完成条件

### S0：参考案例与后端验证

内容：审查一个目标模型的材料、语义和单位，验证候选后端安装；另准备一个可解析求解的简单生灭模型作为计算夹具。整理原始来源与参考结果，不接 LLM。

完成条件：

- 简单夹具与解析解在预定容差内一致。
- 目标文献模型至少有一个明确可重现的结果目标和完整输入记录。
- 列出实际使用与缺失的后端能力；不能把该列表替换为“支持 SBML”。
- 锁定首批依赖与环境，并记录尚未解决的科学问题。

### S1：确定性科学计算闭环

内容：实现最小对象、模型构建、模拟、验证、比较、运行记录与研究包导出。先完成一个模型，再扩大覆盖。

完成条件：

- 同一运行可从冻结输入在干净环境重跑，无 LLM 调用。
- 有效模型通过检查；未定义符号、缺初值、非法数值和不支持语义按预期阻止或失败。
- 参数覆盖、物质量/浓度、固定体积语义通过有区分力的测试，例如使用非单位体积发现遗漏换算。
- 运行成功与验证/比较成功分别呈现。
- 缓存、超时与中断恢复不产生伪成功记录。

### S2：材料提取与证据闭环

内容：指定页面/片段的文献提取、结构化草案、原文位置、方程差异及未解决事项。

完成条件：

- 关键字段有精确证据定位或显式缺失状态。
- 原始材料、提取草案和执行模型之间的变换可追溯。
- 人工修正有记录，单独统计；不把事先手工填好的模型视为自动提取。
- 已知冲突与缺失案例不被静默猜测补齐。

### S3：受约束 Agent 与 A 演示

内容：单 Agent、工具绑定、任务状态、技术恢复、预算、人工科学决定和自动报告。

完成条件：

- 正常、技术失败、材料不足和超出能力四种路径均能形成正确状态与报告。
- 在预设预算内修复有依据的转录/数值问题；不通过改机制修复严格复现。
- 不需人工逐次确认正常工具调用。
- 完成三项核心 A 案例，并公开自主完成率与人工辅助后的结果。

### S4：B 最小闭环

内容：从现象和合成数据构造候选模型，执行有限参数估计、留出预测和候选比较。

完成条件：

- 至少两个结构不同的机制候选及一个简单基线，候选均通过适用的数学检查。
- 模型可以从空草案创建，新增项有假设依据。
- 统一训练/留出协议与预算，比较包含拟合失败、自由参数数量和预测表现。
- 在数据不足子场景中保留不可区分结论；不能强制选择赢家。
- 提出一个带条件限制的区分实验建议，并保存计算依据。

### S5：对照评测与交付

内容：冻结协议，比较通用编程助手、固定流水线和 BioModel Agent，生成完整结果表。

完成条件：

- 基准输入、参考版本、模型/提示版本、预算和全部结果留档。
- 报告正确性、来源与失败指标，不只展示成功图。
- 报告所有人工整理、校验、修正投入，明确哪些步骤尚未自动化。
- 新增一个保留测试模型；若因资源暂缓，明确课程结果只覆盖开发案例。

首期不承诺独立实验数据上的真实机制发现。S4 的合成验证及其局限必须出现在展示和报告中。

## 4. 首批 Benchmark 提案

| 案例 | 用途 | 初始验收目标 | 来源 |
|---|---|---|---|
| 生灭过程解析夹具 | 核验数值与观测处理 | 已知解、单位、初值、采样和误差 | 项目自建，标记为合成测试 |
| Elowitz2000 Repressilator，BIOMD0000000012 | A 核心 | 确定性轨迹、周期/幅度、时间尺度 | [BioModels 模型说明](https://www.ebi.ac.uk/biomodels/services/download/get-files/MODEL6615351360/3/BIOMD0000000012.pdf) |
| Gardner2000 Toggle Switch，BIOMD0000000507 | A 核心 | 不同初值的稳态、指定条件下的切换 | [BioModels 模型说明](https://www.ebi.ac.uk/biomodels/services/download/get-files/MODEL1401190000/3/BIOMD0000000507.pdf) |
| Kholodenko2000 MAPK，BIOMD0000000010 | A 核心 | 反应语义、守恒、反馈与动力学 | [模型仓库](https://github.com/biomodels/BIOMD0000000010/blob/master/README.md) |
| Markevich2004，BIOMD0000000027 | 保留测试候选 | 多位点磷酸化模型与双稳态解释 | [论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC2172246/)、[BioModels 教学材料](https://www.ebi.ac.uk/biomodels/courses/20120427/) |
| 持续刺激下的暂态响应/适应场景 | B | 候选机制构建与留出刺激预测 | 项目自建隐藏生成模型及合成数据 |

上述目标需要逐篇确认实际图号、条件、参数、数值语义及公开材料完整性。登记了模型 ID 不等于参考答案已准备好。若特定图需要随机模型、额外事件或缺失参数，应换成有依据的 ODE 目标或报告不支持，不能伪称完成原图复现。

BioModels 用于参考，不无条件当作不可错的真值。论文、模型文件、策展说明的差异都要保留；如有修正，说明当前评测是在复现哪个版本。

每个 A 案例设置结构化执行和文献重建两条轨道，分开统计。经典模型存在训练数据污染风险；保留模型只避免项目内调参泄漏，不保证基础模型从未见过。

### 故障与缺失案例

初期准备约 12 个衍生案例，并配无故障对照。覆盖：

- 未声明符号、作用域错误或初值遗漏。
- 转录符号错误、时间单位不一致、体积换算错误。
- 材料中无法恢复的参数缺失或不同来源冲突。
- unknown 单位被误当 dimensionless。
- 请求了不支持的 delay/event 等语义。
- 输入导致非有限值或数值求解失败。
- 稳态/振荡特征误判，或参考曲线变量映射错误。

每个案例先写预期处理方式：纠正、拒绝执行、请求决定或保留 unknown。不是每个故障都能被系统凭空识别；无足够依据的错误应通过不匹配或未知状态报告，不要求猜中修复答案。

以模型家族为单位划分开发与测试，避免相似变体跨组泄漏。12 个变体不算作 12 个独立科学模型；报告按模型家族汇总结果。

### B 场景的参考构建

隐藏生成器可从负反馈与非一致前馈等结构中选择，但应先验证参数范围内确实产生目标现象，并构造区分力不同的训练/留出条件。至少一个子场景信息不足。

生成器及其参数不提供给建模系统。系统获得现象、带单位的数据、实验条件、允许使用的机制知识与预算。参数恢复只在可辨识情况下评价；结构比较接受数学等价或观测等价的候选，不能仅因未命中生成器名字判错。

合成成功只证明受控场景下的机制建模与预测能力。后续真实数据可从 [PEtab 基准集合](https://github.com/Benchmarking-Initiative/Benchmark-Models-PEtab) 选择，经范围和数据完整性审查后再接入；首期不承诺完成该集合。

## 5. 验收规则与阈值

所有阈值在盲评前冻结。下面是初值建议；若参考数值误差、图像质量或模型特性不适用，须在运行前更改协议并给理由，不得看到 Agent 结果后放宽。

### 5.1 科学与来源

- 最终交付关键字段的来源/假设状态覆盖率 100%，并人工核对精确引用是否支持对应字段。
- 测试集中观察到的虚构引用、无标记参数补全和隐瞒失败为零。该结果不证明系统在任意输入上绝不会犯错。
- 三项核心 A 均提交完整可重跑研究包；人工修正前后的结果分别统计。
- 核心完整材料任务每项运行 3 次，以至少 8/9 次自主完成作为初始自动化目标。样本很小，只是工程检查，不宣称广泛成功率。
- 检查规则已承诺覆盖的严重错误必须按预期阻止通过。来源歧义检测同时报告精确率、召回率、误报及弃权，不能靠一律拒绝获得高分。

### 5.2 数值参考

对明确的数值参考，定义每个变量固定尺度 `s_j > 0`，比较：

`E_max = max_{j,t} abs(y_agent[j,t] - y_ref[j,t]) / s_j`

初始目标为 `E_max <= 1e-3`，尺度与时间网格在协议中冻结。参考自身的误差应明显小于验收阈值，例如先证实其收敛误差不超过阈值的十分之一；必要时使用解析解或独立算法核验。

不能把 1e-3 当作论文图片数字化或真实实验拟合的通用门槛。图像参考记录提取误差，并单独设计容差。稳态、周期、幅度、切换阈值等均用案例特定协议。相位对齐只有在协议明确允许时使用，并保留未对齐误差。

采用 [SBML Test Suite](https://sbml.org/software/sbml-test-suite/) 中匹配 `ode_core_v1` 的案例核验语义，列出选择规则、覆盖面及不支持项；不能仅用通过的小子集声称完整 SBML 兼容。

### 5.3 B 与拟合

- 候选建立、拟合、留出比较和不确定性/限制报告四个环节均存在。
- 训练集与留出集按实验条件分开，不随机拆相邻时间点冒充独立预测。
- 对合成数据报告预测误差、估计失败率及适用时的参数恢复；不要求不可辨识参数唯一恢复。
- 数据不足案例的正确结论包含不可区分性；所有候选拟合/预测均差时允许全部拒绝。
- 如报告概率区间，明确方法、假设和诊断；未做区间分析则直接说明。

## 6. Agent 价值的对照实验

三组对照：

1. 强通用编程助手：相同基础模型、材料、科学软件可用性和近似资源预算；允许正常工具调用与迭代，不能故意限制为一次回答。
2. 固定工作流：相同领域工具与来源结构，执行预定步骤，没有 LLM 根据诊断动态规划。
3. BioModel Agent：相同基础工具，增加受约束动态决策与修复。

主指标：忠实复现成功率、重大错误、无依据补全、引用正确性、人工修正时间。辅助指标：延迟、调用费用、计算耗时、每次成功的总成本和预算耗尽率。

如模型标识或 API 能力不能严格相同，列出差异，不将结果解释为纯架构因果效应。各组人工介入规则一致；记录失败及其成本。先做小规模成对比较，资源允许时增加重复次数和独立模型家族。

必要的消融：移除来源约束、移除数值验证反馈、移除动态恢复，观察哪部分贡献收益。消融仅用于隔离评测，不改变正常产品的科学检查要求。

如果固定工作流已经达到相同质量且更省成本，优先保留固定流程，动态 Agent 只处理确有收益的节点。如果通用编程助手更强，报告结果并检查工具契约与任务选择，不改指标来制造优势。

## 7. 审查重点与停止条件

每个切片审查其关键科学不变量，优先写有区分力的测试：非单位体积换算、观察映射、分段输入端点、错误状态、修改后旧验证失效、无依据补参、留出泄漏。不要为每个字段 getter 或提示词字面内容写镜像测试。

遇到以下情况应缩小能力范围或补充依据：参考案例本身无法稳定重现；转换损失语义；只在一次 LLM 运行中成功；B 仅扫描原模型参数；报告无法区分原参数和估计参数。完成更多界面或 Agent 角色不能弥补这些问题。

## 8. 关键决策记录

| 决策 | 推荐默认值 | 重新讨论的触发条件 |
|---|---|---|
| 运行结构 | 模块化单体 + 独立计算进程 | 并发与资源实测超出本地能力 |
| Agent | 单个逻辑 Agent + 有状态工作流 | 公平对照显示多 Agent 的稳定收益 |
| 模型真值 | 版本化 SBML 负载 + 外置研究元数据 | 首个必须使用其他数学类型的真实任务 |
| 数值后端 | libRoadRunner 为主，独立参考核验 | 必需语义或估计性能不满足 |
| 参数估计 | 小规模、明确似然/残差、多起点 | 需要高效灵敏度和更完整不确定性工具 |
| 标准互操作 | 受限自有协议，借鉴 SED-ML/PEtab | 出现具体外部导入导出需求 |
| 存储 | 不可变文件 + SQLite | 跨项目复杂检索/多人并发成为实际问题 |
| 界面 | CLI/Notebook 先行 | 科学闭环稳定，需要可视化审查与交互 |

实现者变更决策时使用简短 ADR：问题、选择、替代方案、科学影响、工程代价、验证证据。无需为每个小实现细节创建 ADR。
