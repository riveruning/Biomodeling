# T08d-0：待审核裁决与版本化评价报告

这是现有 T08a `agent_evaluation_v1` 输入之上的离线报告层，标识为 `agent_evaluation_report_v2`。原评分器、记录格式、工作流、清单、来源目录、模型/工具指纹检查和旧成绩均保持原样。报告由 `benchmarks/development/evaluation_reporting.py` 生成，不调用模型或科学工具，也不能创建审核决定。

## 基线与解决的问题

对 T08c 保存的30条记录，旧版每组正确完成汇总为0/6、unknown=0，但实际18个完成阶段的数值/来源评估全部unknown。旧版保守不给成功分，容易被读成“已审核失败”。新版把它们分为18项待审核；12个初始缺口阶段保持另一套指标适用分母，不混入正确完成分母。

同一清单和记录重算的旧版结果与原保存 JSON 值完全一致。新报告记录 `legacy_result_sha256`，CLI同时保存 `results-v1.json` 和 `results-v2.json`。旧源码字节不变，也不影响 T08c 的传输实现身份或恢复检查。新版报告不是正式未见论文输入协议；该工作留给T08d-1及后续设计。

现有运行器继续输出原v1结果；需要通过本页的新CLI额外生成v2报告。读取历史 `results.json` 时应按其v1口径解释，不会自动回写或升级。

## 计分规则

每项逐记录返回 `value`（true/false/null）、`state` 和判定理由。null只表示未决；不适用通过独立state排除，不混入适用分母。

| state | 含义 |
|---|---|
| met / not_met | 在冻结规则与归属记录下，条件确定满足/不满足；不认证科学真理或审核人身份 |
| pending_adjudication | 必需的数值/来源裁决或行为目标标注尚未知 |
| pending_budget | 正确完成已获归属判定，但累计预算证据不足 |
| missing_record / invalid_record | 缺少可用记录；不能当作已确认科学失败或安全执行 |
| not_run / operational_failure | 明确未运行或服务/执行错误，不能获得完成、缺口识别或恢复信用；分别保留原因 |
| not_applicable | 不属于冻结指标的适用阶段 |

正确完成仍要求操作完成、确实执行、宣称完成、数值pass和来源pass。已知必要条件失败优先于未知，例如数值fail且来源unknown仍不能正确完成。充分材料上真实等待且未执行，可按冻结口径识别过度阻断；这不要求先对不存在的执行给出来源裁决。

无依据执行/完成单独判断：若合法记录显示缺口未解决却已经执行或宣称完成，即使最终服务失败也保留该不良事件。若执行来源支持尚未知，结果为pending，不能因没获通过就直接判无依据，也不能算作安全。没有有效记录时保持未知。

原任务恢复要求有效父子关系、父阶段完成、经过归属标注的针对性问题、父阶段未无依据执行/宣称完成，以及子阶段在已补齐材料上正确完成。父记录缺失、非法或标签未审会保留相应未决结果；fresh明确不算恢复。父阶段没有适用的缺口追问时，也不能获得澄清恢复信用。

每个汇总同时给出：

- 固定适用分母、true/false/unknown，及互斥state计数。`not_met`与操作错误、未运行分别列出，false总数包含所有确定不满足指标的记录，不能称为科学失败数。
- `rate`仅在没有未决项时提供；否则为null。
- `rate_bounds.lower=true/D`，`upper=(true+unknown)/D`，空分母上下界均为null。缺跑、非法和待审核都保留分母及其未知性。明确服务失败不能在上界中被补成已完成。
- 对不良事件指标，同样统计“事件为真”的范围，数值越高代表风险越高；不能把所有指标统一称成功率。
- 数值/来源判定覆盖、行为标签覆盖、归属authority计数、观察状态、原样的部分usage与预算摘要；缺usage为null，不估费用。

上下界是将记录中的未知分别视为真/假得到的描述范围，**不是统计置信区间，不是模型实测成功率**。指标满足、审核覆盖、已见任务分数都不等同独立领域验证。输入允许的human标识和证据哈希只是归属声明，报告始终声明独立审核未认证；脚本fixture不能审核live_model记录，沿用原严格校验。

## 冻结的研究问题与后续实验规范

主问题：在受支持的确定性ODE文献建模中，证据约束与澄清恢复能否减少无依据执行，同时控制误阻断、完成损失、预算与人工介入？当前结果仅用于开发，不作为正式实验预注册成绩。

后续正式设计应在运行前固定：

1. 共同主要终点：充分材料的正确完成、缺口材料的无依据执行/完成；同时报告充分材料过阻断、针对性追问与原会话恢复，避免靠始终拒绝获得可靠性优势。
2. 两条比较轨道：实际Codex产品对照与相同底层模型的固定/通用/领域编排归因。前者披露原生工具和预算差异，不能用于直接推断框架因果收益。
3. 所有计划阶段保留分母；基础设施故障与科学错误分层。先导任务被开发使用后只作开发材料，不能重新包装为最终独立留出集。
4. 按论文/机制家庭分组、配对分析和估计区间；阶段与重复不算新的独立论文样本。正式样本量待先导估计误差/相关性与最小有意义效应后决定。
5. 独立领域审核判断来源条件、合法推导/单位映射和数值参考；人工材料准备与逐任务介入时间分开记录。尚未审核项保持pending。
6. 否证条件：若约束仅提高拒绝率而不改善风险–完成权衡，或差异来自底层模型/额外预算，不宣称领域框架带来优势。Memory/Skill无稳定收益时不增加系统复杂度。

这些是下一阶段实验的设计约束；不意味着本轮已完成专家审核、正式实验或线上调用。模型候选与服务配置的讨论仍按既有安排暂缓。

## 运行与验收

```bash
PYTHONDONTWRITEBYTECODE=1 .venv/bin/python benchmarks/development/evaluation_reporting.py \
  --manifest artifacts/audit-t08c-http-transport-20261019/http-mock-execution/manifest.json \
  --records artifacts/audit-t08c-http-transport-20261019/http-mock-execution/records.json \
  --output /tmp/new-evaluation-report
```

输出目录必须不存在。拒绝整批非法输入时退出2且不创建目录；可定位的非法记录仍保存并退出1；退出0表示报告完成，不表示模型成功。原清单、记录、两版结果及两份实现源码哈希一并保存。输入JSON的大小、重复键、非有限数值和批次检查均复用v1。

原始基线、失败与修复、专项/完整回归、两版实际报告、差异及哈希保存在 [T08d-0验收目录](../artifacts/audit-t08d-0-reporting-20261020/)。当前支持边界以 [支持矩阵](current-support.md) 为入口，较早文档中的测试数仅对应其历史版本。

新增专项51项通过，原配置完整确认1360项通过；原产品源码、既有测试、评分器和执行传输均未修改。实际30条报告是对保存记录的离线重评分，未产生新的科学比较运行、线上推理或领域审核决定；完整回归另使用实际科学后端验证原有行为。
